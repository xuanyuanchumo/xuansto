# 角色管理司 (Role Management Si)

> 尚书省 · 吏部 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 角色定义与创建 | SCRIPTED_BATCH | 90% | 基于模板标准化创建，高度结构化 |
| 权限矩阵维护 | HYBRID_ASSISTED | 85% | 工具辅助 + 安全专家审核 |
| 职责边界审计 | AUTONOMOUS_MANUAL | 78% | 需要理解业务流程和组织架构 |
| 角色继承体系设计 | AUTONOMOUS_MANUAL | 72% | 架构级决策，影响深远 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（读取现有角色定义、权限配置、RBAC策略）
- **写操作**: Write, SearchReplace（创建角色模板、更新权限矩阵）
- **批量操作**: RBAC策略生成器、权限合规扫描器、角色同步脚本
- **验证操作**: 权限模拟测试工具、最小权限验证器

### 注意事项
- ⚠️ 遵循最小权限原则(POLP)：角色只授予完成任务所需的最小权限集合
- ⚠️ 角色爆炸(Role Explosion)风险：粒度过细会导致管理成本指数增长，需权衡
- ⚠️ 权限变更必须经过审批流程，禁止临时授予永久权限
- ✅ 采用"职责分离"(SoD)原则：敏感操作需要多人协作完成（如制单+审核）
- ✅ 建立角色生命周期管理：创建 → 审批 → 发布 → 定期review → 归档/废弃

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| CONFIG | RBAC策略文件(YAML/JSON) | EXCLUSIVE (修改) |
| DATABASE | 身份认证系统(IdP/AD) | HIGHLY_RESTRICTED |
| FILE | /docs/role-definitions/ | SHARED (读) / EXCLUSIVE (写) |
| API | 权限管理API | AUTHENTICATED + AUDITED |
| SECRET | 角色关联的密钥/凭证 | ENCRYPTED + ACCESS_CONTROLLED |

### 竞争规避策略
1. **变更窗口隔离**: 权限变更在维护窗口期批量执行，避免频繁零散修改
2. **版本化管理**: 角色定义采用版本控制，支持回滚和审计追踪
3. **灰度发布机制**: 新角色先在小范围试点，验证无误后再全面推广

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 角色权限全景图公开：所有角色及其权限范围以可视化的方式展示给管理员
- 变更审计 trail 完整：谁在什么时间修改了什么权限、原因是什么，全程可查
- 合规报告自动生成：定期输出权限合规报告，标识过度授权和权限孤岛

### OpenClaude 编排
- 智能角色推荐：根据用户的职责描述，自动推荐合适的角色组合
- 权限异常检测：监测异常的权限申请模式（如突然申请高权限、离职前大量下载）
- 自动化权限回收：员工离职/转岗时自动触发权限回收流程，防止权限残留

### Claw-Code 契约驱动
- 权限即代码(Policy as Code): 使用OPA/CASBIN等工具将权限策略声明式定义并可测试
- 访问控制自动化测试：编写测试用例验证权限模型的正确性（正向/反向测试）
- 定期权限卫生检查：自动化脚本定期扫描并清理未使用的角色和过度授权
