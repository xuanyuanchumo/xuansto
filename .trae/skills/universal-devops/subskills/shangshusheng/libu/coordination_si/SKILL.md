# 协调司 (Coordination Si)

> 尚书省 · 吏部 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 冲突检测与预警 | SCRIPTED_BATCH | 93% | 基于规则自动识别资源冲突和时间冲突 |
| 进度同步报告生成 | SCRIPTED_BATCH | 96% | 数据聚合自动化，模板化输出 |
| 协调会议组织 | HYBRID_ASSISTED | 82% | 自动收集议题 + 人工主持会议 |
| 复杂依赖关系协调 | AUTONOMOUS_MANUAL | 72% | 涉及多方利益平衡，需要谈判技巧 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（读取各团队进度、依赖关系图、资源占用情况）
- **写操作**: Write, SearchReplace（编写协调纪要、更新进度跟踪表）
- **批量操作**: 依赖分析脚本、冲突检测扫描器、进度汇总ETL
- **验证操作**: 一致性检查工具（确认各方信息同步）

### 注意事项
- ⚠️ 协调者必须保持中立公正，避免偏向任何一方导致信任危机
- ⚠️ 冲突升级应及时，不要试图掩盖问题或"私下解决"
- ✅ 采用"单一事实来源"(Single Source of Truth)原则：所有进度数据来自统一系统
- ✅ 建立"无指责文化"(Blameless Culture)：聚焦问题解决而非追责

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| FILE | /docs/project-plans/ | SHARED (读) |
| DATABASE | 项目管理系统(Jira/Trello) | STATEFUL |
| CALENDAR | 团队日历(Outlook/Google) | READ_ONLY (查询) / RESERVED (预订) |
| API | 即时通讯平台(Slack/钉钉) | REAL_TIME |
| DOCUMENT | 协作文档(Confluence/飞书) | SHARED (协作编辑) |

### 竞争规避策略
1. **时间分片协商**: 共享资源的访问采用时间片轮转，提前预约避免临时争抢
2. **依赖可视化**: 使用依赖关系图(DAG)明确展示任务间的前后置关系，识别关键路径
3. **缓冲区设计**: 在关键路径上预留时间缓冲(buffer)，吸收不确定性带来的延误

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 所有协调决策公开：资源分配、优先级调整的理由对所有stakeholder可见
- 冲突解决过程留痕：每次协调会议的决议、action items、责任人都有完整记录
- 进度偏差透明化：项目延期、风险升级及时通报，不隐瞒坏消息

### OpenClaude 编排
- 智能冲突预测：基于历史数据和当前状态，提前预警可能的资源冲突和瓶颈
- 自动化协调工作流：常规的进度同步、状态更新可通过bot自动完成，减少人工干预
- 最优路径推荐：当出现多个可行的协调方案时，推荐总体最优解（考虑时间、成本、风险）

### Claw-Code 契约驱动
- SLA响应时效契约：定义不同级别协调请求的响应时限（紧急: 1h, 一般: 4h, 低优: 24h）
- 闭环追踪机制：每个协调事项都有唯一的tracker，直到完全解决才关闭
- 定期对齐仪式：建立每周sync ritual，强制性地同步进展和对齐预期
