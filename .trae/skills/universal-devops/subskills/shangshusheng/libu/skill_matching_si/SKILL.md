# 技能匹配司 (Skill Matching Si)

> 尚书省 · 吏部 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 技能图谱构建 | SCRIPTED_BATCH | 91% | 基于元数据和标签自动聚合 |
| 能力评估打分 | HYBRID_ASSISTED | 84% | 算法初评 + 人工校准 |
| 任务-Agent匹配 | SCRIPTED_BATCH | 94% | 基于匹配算法自动推荐 |
| 技能差距分析 | AUTONOMOUS_MANUAL | 76% | 需要结合业务发展判断培训优先级 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（读取Agent技能标签、历史表现数据、任务需求）
- **写操作**: Write, SearchReplace（更新技能评分、生成匹配报告）
- **批量操作**: 技能提取pipeline、匹配度计算引擎、推荐算法服务
- **验证操作**: A/B测试框架（对比不同匹配策略的效果）、准确率统计工具

### 注意事项
- ⚠️ 避免"冷启动"问题：新Agent缺乏历史数据时，采用基于元数据的启发式匹配
- ⚠️ 匹配算法需持续优化：定期回测历史数据，调整特征权重和模型参数
- ✅ 采用"多维度评估"：不仅看技能匹配度，还要考虑可用性、成本、历史质量
- ✅ 建立反馈闭环：任务完成后收集满意度反馈，用于改进匹配模型

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| DATABASE | 技能图谱数据库 | SHARED (读) / EXCLUSIVE (写入) |
| CACHE | 匹配结果缓存(Redis) | TTL_BASED (定时过期) |
| MODEL | 匹配算法模型文件 | VERSIONED (版本化管理) |
| LOG | 匹配历史日志 | APPEND_ONLY |
| API | Agent能力注册接口 | RATE_LIMITED |

### 竞争规避策略
1. **读写分离**: 高频读取技能数据通过缓存层，降低主库压力
2. **异步匹配**: 匹配计算采用异步队列处理，避免阻塞请求
3. **降级策略**: 当匹配服务不可用时，退化为简单的轮询(Round-Robin)分配

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 匹配逻辑开源透明：核心匹配算法和评分公式对技术团队开放审查
- 技能数据民主化：Agent可以查看自己的技能画像和排名，了解改进方向
- 匹配效果公开：定期发布匹配准确率、用户满意度等指标，接受监督

### OpenClaude 编排
- 动态技能发现：自动识别Agent的新技能（通过代码分析、任务完成情况推断）
- 上下文感知匹配：考虑任务的紧迫程度、重要性、特殊要求等因素进行智能匹配
- 持续学习优化：利用强化学习根据任务完成质量动态调整匹配策略

### Claw-Code 契约驱动
- 匹配质量SLA契约：定义匹配推荐的准确率目标（如Top-3推荐命中率>80%）
- 技能标准统一契约：建立统一的技能分类体系和评级标准，确保跨团队可比
- 反馈驱动的改进循环：将用户反馈作为信号输入模型再训练，形成持续优化闭环
