# 代码生成司 (Code Generation Si)

> 尚书省 · 工部 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 脚手架项目创建 | SCRIPTED_BATCH | 97% | CLI工具(create-* / scaffold)高度成熟 |
| CRUD代码生成 | SCRIPTED_BATCH | 94% | 基于模板和数据模型批量生成 |
| 代码片段复用 | SCRIPTED_BATCH | 95% | Snippet/Templates系统标准化 |
| 自定义模板开发 | HYBRID_ASSISTED | 82% | AI辅助 + 人工调优细节 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（读取模板文件、数据模型定义、架构规范）
- **写操作**: Write, SearchReplace（生成代码文件、更新脚手架模板）
- **批量操作**: 代码生成器(Cookiecutter/Hygen/plop)、脚手架CLI、Snippet管理器
- **验证操作**: 生成代码的lint检查、类型检查、编译验证

### 注意事项
- ⚠️ 生成的代码不是最终产物：只是起点，仍需根据具体业务逻辑定制和优化
- ⚠️ 避免过度抽象：模板太灵活会导致复杂度爆炸，找到"恰到好处"的抽象层次
- ✅ 采用"约定优于配置": 提供合理的默认值和最佳实践，减少开发者决策负担
✅ 保持生成的代码可读性：不要为了省几行代码而牺牲可维护性和可理解性

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| TEMPLATE | /templates/ /scaffolds/ | SHARED (读) / EXCLUSIVE (修改) |
| OUTPUT | 生成的项目代码 | USER_OWNED (用户自由修改) |
| CONFIG | 代码生成器配置文件 | VERSION_CONTROLLED |
| MODEL | 数据模型/接口定义 | SINGLE_SOURCE_OF_TRUTH |
| SNIPPET | 代码片段库 | COMMUNITY_CONTRIBUTED |

### 竞争规避策略
1. **模板版本锁定**: 项目一旦使用某版本模板生成，后续升级需显式迁移而非隐式覆盖
2. **生成标记保留**: 生成的代码包含`@generated`注释，便于区分手动编辑和自动生成部分
3. **增量生成能力**: 支持在已有项目上增量生成新模块，而非只能从头开始

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 模板完全开源：所有脚手架模板对团队成员开放审查和贡献
- 生成逻辑透明：代码生成器的转换规则和决策逻辑有完整文档说明
- 最佳实践内嵌：模板中体现的架构模式和编码规范有详细注释解释原因

### OpenClaude 编排
- 智能脚手架定制：根据用户的技术栈选择和项目特征，自动调整生成的代码结构
- 上下文感知补全：基于当前项目的已有代码风格，生成与之一致的新代码
- 模板效果反馈循环：收集用户对生成代码的满意度反馈，持续改进模板质量

### Claw-Code 契约驱动
- 生成代码质量门禁：生成的代码必须通过lint/type-check/test才能交付给用户
- 模板向后兼容承诺：模板升级不破坏已生成项目的正常编译和运行
- 定期 freshness 审计：定期review模板是否反映了最新的技术最佳实践和安全要求
