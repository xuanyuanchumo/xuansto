# 模板管理司 (Template Management Si)

> 尚书省 · 礼部 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 模板实例化渲染 | SCRIPTED_BATCH | 98% | Jinja2/Mustache/Handlebars引擎高度成熟 |
| 模板开发与设计 | HYBRID_ASSISTED | 82% | AI辅助布局 + 人工调整细节 |
| 模板版本管理 | SCRIPTED_BATCH | 96% | Git版本控制 + 语义化版本号 |
| 模板库整理归档 | SCRIPTED_BATCH | 93% | 自动化分类、标记过期模板 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（读取模板源码、变量定义、继承关系）
- **写操作**: Write, SearchReplace（创建新模板、更新变量占位符）
- **批量操作**: 模板渲染引擎、变量提取脚本、模板依赖分析器
- **验证操作**: 模板语法检查器(lint)、渲染结果对比(diff)、变量完整性校验

### 注意事项
- ⚠️ 模板应保持简洁：避免过度嵌套和复杂逻辑，模板层只负责展示
- ⚠️ 变量命名要语义化：使用描述性名称如`{{user.email}}`而非`{{x}}`
- ✅ 采用"模板继承"机制：公共布局(Header/Footer)定义为base template，减少重复
- ✅ 建立"模板目录": 提供模板清单和使用说明，降低发现和学习成本

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| FILE | /templates/ | SHARED (读) / EXCLUSIVE (写) |
| REGISTRY | 模板注册中心 | READ_ONLY (查询) / ADMIN (管理) |
| CACHE | 编译后的模板缓存 | INVALIDATE_ON_CHANGE |
| VARIABLE | 变量定义文件(schema) | VERSION_CONTROLLED |
| OUTPUT | 渲染输出产物 | EPHEMERAL (临时生成) |

### 竞争规避策略
1. **模板命名空间隔离**: 不同团队的模板使用独立目录前缀，避免名称冲突
2. **向后兼容承诺**: 模板升级必须保持旧变量的兼容性，提供migration guide
3. **灰度发布能力**: 新模板可以先在非关键文档上试用，验证无误后再全面推广

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 模板库完全开放：所有团队成员可浏览、复用、贡献模板
- 版本变更日志完整：每次模板更新的内容、原因、影响范围清晰记录
- 使用统计透明化：哪些模板最受欢迎、哪些长期无人问询，数据指导优化方向

### OpenClaude 编排
- 智能模板推荐：根据文档类型和内容特征，自动推荐最合适的模板
- 变量自动补全：基于模板schema提供IDE级别的变量提示和校验
- 模板效果预览：实时预览渲染效果，所见即所得(WYSIWYG)

### Claw-Code 契约驱动
- 模板Schema验证：定义严格的变量类型和必填项，渲染前自动校验
- 模板测试覆盖：为核心模板编写单元测试，确保渲染输出的正确性
- 模板生命周期管理：定义模板的创建→活跃→维护→弃用→归档的全生命周期流程
