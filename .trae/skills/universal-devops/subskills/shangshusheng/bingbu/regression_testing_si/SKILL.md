# 回归测试司 (Regression Testing Si)

> 尚书省 · 兵部 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 冒烟测试执行 | SCRIPTED_BATCH | 97% | 高度自动化，快速反馈 |
| 回归套件筛选 | HYBRID_ASSISTED | 86% | 基于变更影响分析(AI) + 人工确认 |
| 全量回归执行 | SCRIPTED_BATCH | 95% | 并行化执行，标准化流程 |
| 失败用例分析 | AUTONOMOUS_MANUAL | 78% | 需要理解根因和业务影响 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（读取测试用例、变更日志、历史失败记录）
- **写操作**: Write, SearchReplace（编写回归报告、更新测试优先级）
- **批量操作**: 测试调度框架(Jenkins/TestGrid)、并行执行引擎、结果聚合脚本
- **验证操作**: 测试稳定性分析(Flaky test detection)、回归通过率统计

### 注意事项
- ⚠️ 回归测试不是越多越好：维护成本随用例数增长，需平衡覆盖率和效率
- ⚠️ 关注Flaky Test(不稳定测试)：频繁误报会降低团队对测试结果的信任度
- ✅ 采用"影响驱动回归": 只运行受变更影响的用例子集，大幅缩短反馈时间
- ✅ 建立"P0/P1/P2"分级体系：核心链路必须全量回归，边缘功能可抽样

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| TEST_SUITE | 回归测试用例库 | SHARED (读) / EXCLUSIVE (更新) |
| ENVIRONMENT | 测试环境(Staging/QA) | RESERVED (测试期间独占) |
| DATABASE | 测试结果数据库 | APPEND_ONLY |
| QUEUE | 测试任务队列 | PRIORITY_BASED |
| REPORT | 回归报告输出 | VERSIONED (按构建号) |

### 竞争规避策略
1. **测试环境分时复用**: 多个回归任务按时间片轮流使用共享环境，避免长时间占用
2. **用例锁机制**: 正在被执行的用例标记为"running"，防止重复执行浪费资源
3. **智能重试策略**: 失败用例自动重试1-2次（排除偶发环境问题），仍失败才告警

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 回归结果完全公开：所有团队成员可查看每次回归的通过率、失败详情、耗时分布
- 用例质量指标可视：哪些用例经常Flaky、哪些从未失败过、哪些最有价值，数据说话
- 变更影响分析透明：为什么选择这些用例进行回归，影响分析的依据和逻辑公开

### OpenClaude 编排
- 智能用例选择：基于代码变更的AST分析和依赖图谱，精准推荐需要回归的用例子集
- 失败聚类分析：自动将失败的用例按根因分类（环境问题/代码bug/数据问题），辅助快速定位
- 回归时间预估：基于历史数据和当前用例集规模，准确预估回归耗时，帮助规划发布窗口

### Claw-Code 契约驱动
- 回归通过率SLA：定义P0用例100%通过、整体通过率>95%等硬性指标
- Flaky Test零容忍：连续3次运行的用例如果结果不一致，自动标记为Unstable并暂停执行
- 回归时效性约束：冒烟测试<30分钟、全量回归<4小时（根据项目规模调整）
