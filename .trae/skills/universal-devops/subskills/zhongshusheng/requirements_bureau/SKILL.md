# 需求分析局 (Requirements Bureau)

> 中书省 · 决策层 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 需求文档编写 | AUTONOMOUS_MANUAL | 85% | 需要深入理解业务上下文，人工决策占比高 |
| 用户故事拆解 | SCRIPTED_BATCH | 90% | 可按模板标准化拆解，适合批量处理 |
| 优先级排序分析 | AUTONOMOUS_MANUAL | 75% | 涉及多方利益平衡，需综合判断 |
| 验收标准制定 | HYBRID_ASSISTED | 80% | 结合自动生成与人工审核 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（查找现有需求文档、代码实现）
- **写操作**: Write, SearchReplace（创建PRD、用户故事文档）
- **批量操作**: 需求模板引擎脚本、优先级矩阵计算工具
- **验证操作**: 需求完整性检查清单、一致性验证工具

### 注意事项
- ⚠️ 需求变更必须追溯影响范围，避免遗漏关联模块
- ⚠️ 优先级排序需考虑技术债务、业务价值、依赖关系三维指标
- ✅ 采用INVEST原则（Independent, Negotiable, Valuable, Estimable, Small, Testable）评估用户故事质量
- ✅ 所有需求文档应包含明确的验收条件和完成定义（DoD）

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| FILE | /docs/requirements/ | SHARED (读) |
| FILE | /docs/prd/ | EXCLUSIVE (写) |
| FILE | /docs/user-stories/ | SHARED (读) / EXCLUSIVE (写) |
| CODEBASE | 业务逻辑代码目录 | SHARED (读) |
| API | 产品管理系统接口 | RATE_LIMITED |

### 竞争规避策略
1. **需求锁定机制**: 同一需求文档编辑时获取排他锁，避免多人同时修改导致冲突
2. **版本分支策略**: 大型需求采用feature branch隔离，完成后合并至主分支
3. **依赖声明机制**: 需求间的依赖关系显式声明，支持拓扑排序和并行开发

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 需求决策过程公开可追溯：每个需求的优先级调整记录原因和决策者
- 需求评审会议纪要共享：所有stakeholder可见评审结论和遗留问题
- 变更日志透明化：需求变更的影响范围、风险评估全程留痕

### OpenClaude 编排
- 智能需求分解引擎：根据复杂度自动选择深度拆解或快速处理路径
- 多角色协同编排：自动协调产品经理、技术负责人、测试人员的需求对齐会议
- 依赖关系图动态维护：实时更新需求间的前后置依赖，优化开发顺序

### Claw-Code 契约驱动
- 需求-代码双向追踪契约：PRD中的每个功能点映射到具体代码实现位置
- 验收标准即测试用例：将AC转化为自动化测试，确保交付符合预期
- 需求完成度量化指标：通过代码覆盖率、测试通过率等客观数据衡量需求落地情况
