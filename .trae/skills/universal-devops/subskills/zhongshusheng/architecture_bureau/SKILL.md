# 架构设计局 (Architecture Bureau)

> 中书省 · 决策层 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 架构设计文档编写 | AUTONOMOUS_MANUAL | 80% | 需要全局视角和技术深度判断 |
| 技术选型评估 | AUTONOMOUS_MANUAL | 75% | 涉及多维度权衡（性能/成本/生态） |
| 构图生成（架构图/时序图） | SCRIPTED_BATCH | 92% | 基于PlantUML/Mermaid模板标准化输出 |
| 架构评审准备 | HYBRID_ASSISTED | 85% | 自动收集指标 + 人工撰写评审材料 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（分析现有架构、设计模式）
- **写操作**: Write, SearchReplace（创建ADR、架构文档）
- **批量操作**: PlantUML渲染脚本、架构决策记录(ADR)模板生成器
- **验证操作**: 架构合规性检查工具、性能基线对比脚本

### 注意事项
- ⚠️ 架构决策必须记录决策背景和备选方案（ADR格式），便于后续审查
- ⚠️ 技术选型需考虑团队熟悉度、社区活跃度、长期维护成本
- ✅ 遵循SOLID原则和领域驱动设计（DDD）方法论
- ✅ 架构设计应预留扩展点，支持未来演进而不破坏现有接口

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| FILE | /docs/architecture/ | EXCLUSIVE (写) |
| FILE | /docs/adr/ | SHARED (读) / EXCLUSIVE (写) |
| CODEBASE | 核心模块入口文件 | SHARED (读) |
| CONFIG | 基础设施配置文件 | SHARED (读) / EXCLUSIVE (修改) |
| API | 技术栈版本管理服务 | READ_ONLY |

### 竞争规避策略
1. **架构冻结窗口期**: 在迭代初期完成核心架构设计，中期只允许微调
2. **ADR编号唯一性**: 全局统一分配架构决策记录编号，避免冲突
3. **分层审批流程**: 核心架构变更需多级review，非核心变更可快速通道

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 架构决策完全公开：所有ADR文档对团队成员开放，包括被否决的方案及原因
- 技术选型论证过程透明：性能基准测试数据、成本估算模型均可查阅
- 架构演进路线图可视：当前架构到目标架构的迁移计划和时间节点清晰呈现

### OpenClaude 编排
- 智能架构模式推荐：根据业务特征自动匹配合适的设计模式（微服务/单体/Serverless）
- 影响范围自动分析：架构变更时自动识别受影响的模块和服务，生成依赖图谱
- 技术债务跟踪编排：持续监控架构腐化程度，触发重构建议

### Claw-Code 契约驱动
- 架构约束即代码：通过ArchUnit等工具将架构规则转化为自动化测试
- 接口契约前置定义：API设计先行，使用OpenAPI/Swagger规范确保前后端一致
- 非功能性需求量化：性能指标（延迟/吞吐量）、可用性SLA写入可执行规格说明书
