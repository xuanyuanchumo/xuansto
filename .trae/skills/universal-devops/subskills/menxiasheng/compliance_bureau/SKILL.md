# 合规审计局 (Compliance Bureau)

> 门下省 · 审核层 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 合规检查清单执行 | SCRIPTED_BATCH | 92% | 标准化检查项，适合自动化扫描 |
| 合规报告编写 | HYBRID_ASSISTED | 85% | 数据收集自动化 + 人工撰写结论 |
| 合规差距分析 | AUTONOMOUS_MANUAL | 78% | 需要专业判断和风险评估 |
| 审计证据收集 | SCRIPTED_BATCH | 90% | 结构化收集日志、配置、截图等 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（检查配置文件、权限设置、日志）
- **写操作**: Write, SearchReplace（生成合规报告、整改建议书）
- **批量操作**: 合规扫描脚本、配置合规性检查工具
- **验证操作**: 合规规则引擎、审计轨迹完整性校验工具

### 注意事项
- ⚠️ 合规要求可能随法规变化而更新，必须建立持续监控机制
- ⚠️ 审计证据必须具备不可篡改性，建议采用区块链或WORM存储
- ✅ 采用"默认合规"原则：系统设计阶段就内置合规控制，而非事后补救
- ✅ 建立合规知识库：整理常见合规模式和反模式，降低重复劳动

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| FILE | /docs/compliance/ | EXCLUSIVE (写报告) |
| FILE | /config/security-policies/ | SHARED (读) |
| LOG | 系统操作日志 | READ_ONLY (审计用途) |
| CONFIG | 访问控制配置 | SHARED (读) / EXCLUSIVE (修改) |
| DATABASE | 合规审计数据库 | APPEND_ONLY (不可删除) |

### 竞争规避策略
1. **审计窗口期预约**: 大规模合规审计前提前通知相关团队，预留配合时间
2. **证据锁定机制**: 审计期间的关键配置和数据快照锁定，防止被篡改
3. **分级响应流程**: 不同级别的合规事件触发不同的响应团队和处理SLA

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 合规状态仪表盘公开：实时展示各项合规指标的达成情况，红灯/黄灯/绿灯直观可见
- 审计发现透明化：合规问题的发现、整改进度、最终结果全程可追溯
- 政策变更通知机制：合规政策调整时自动通知所有受影响的系统和团队

### OpenClaude 编排
- 智能合规映射：自动将业务需求映射到对应的合规条款和控制措施
- 风险预测模型：基于历史违规数据和行业案例，预测潜在的高风险区域
- 整改任务自动分解：将合规差距自动转化为可执行的整改任务，分配给对应负责人

### Claw-Code 契约驱动
- 合规即代码(Compliance as Code): 将合规规则转化为可执行的自动化测试（如OPA/Rego策略）
- 审计轨迹不可变性：关键操作的审计日志采用append-only存储，满足法规取证要求
- 持续合规验证：在CI/CD pipeline中嵌入合规检查步骤，确保每次部署都符合既定标准
