# 测试验证局 (Testing Bureau)

> 门下省 · 审核层 · Universal DevOps v4.0

**状态**: 占位符 - 具体内容由后续任务填充

## 🤖 自主化操作指南 (v7.0)

### 推荐操作模式
| 操作场景 | 推荐模式 | 置信度 | 说明 |
|---------|---------|--------|------|
| 测试用例编写 | HYBRID_ASSISTED | 85% | AI辅助生成 + 人工调整边界条件 |
| 测试执行与监控 | SCRIPTED_BATCH | 95% | CI流水线自动化执行 |
| 缺陷定位与分析 | AUTONOMOUS_MANUAL | 80% | 需要结合代码逻辑和业务场景 |
| 测试策略制定 | AUTONOMOUS_MANUAL | 75% | 需要平衡覆盖率和成本效益 |

### 常用工具组合
- **读操作**: Read, SearchCodebase, Grep（分析被测代码、理解业务逻辑）
- **写操作**: Write, SearchReplace（编写测试用例、测试数据准备脚本）
- **批量操作**: Jest/Mocha/Pytest测试套件、性能基准测试脚本
- **验证操作**: 覆盖率报告生成器、缺陷追踪系统集成

### 注意事项
- ⚠️ 测试用例应独立可重复，避免依赖外部状态或执行顺序
- ⚠️ Mock使用需谨慎，过度mock会导致测试无法捕获真实集成问题
- ✅ 遵循测试金字塔：单元测试 > 集成测试 > E2E测试，数量递减成本递增
- ✅ 采用Given-When-Then格式编写BDD风格测试，提升可读性和业务对齐度

## 🔗 资源协调要点 (v7.0)

### 常访问资源
| 资源类型 | 典型路径 | 锁策略建议 |
|---------|---------|-----------|
| FILE | /tests/ | SHARED (读) / EXCLUSIVE (写新用例) |
| FILE | /test-data/ | SHARED (读) / EXCLUSIVE (修改) |
| CODEBASE | 被测模块源码 | SHARED (读) |
| API | 测试管理平台接口 | STATEFUL |
| ENVIRONMENT | 测试环境（Staging/QA） | RESERVED (测试期间独占) |

### 竞争规避策略
1. **测试数据隔离**: 每个测试用例使用独立的数据集，避免并发执行时相互干扰
2. **环境分时复用**: 多个测试套件按时间片轮流使用共享测试环境
3. **失败用例快速反馈**: 测试失败时立即通知相关开发者，减少阻塞时间

## 💡 开源哲学应用 (v7.0)

### OpenCode 透明化
- 测试覆盖率实时公开：每次构建后自动发布覆盖率报告，所有团队成员可见
- 缺陷发现过程透明：从测试执行到缺陷确认的全链路记录，支持复盘根因
- 测试策略文档共享：测试计划、测试用例设计思路对所有开发者开放查阅

### OpenClaude 编排
- 智能测试用例推荐：基于代码变更自动推荐需要补充的回归测试用例
- 失败聚类分析：自动识别频繁失败的测试用例类别，定位系统性问题
- 测试资源动态调度：根据测试队列长度和优先级，自动分配并行测试资源

### Claw-Code 契约驱动
- 测试即文档：良好的测试用例本身就是最佳的业务需求说明
- 质量门槛契约：定义最低覆盖率要求（如行覆盖率>80%、分支覆盖率>70%）作为合入条件
- 缺陷修复SLA：根据严重等级设定修复时限（Critical: 24h, Major: 72h, Minor: 1sprint），超时自动升级
