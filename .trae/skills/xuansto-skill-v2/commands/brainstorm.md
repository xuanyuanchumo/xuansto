# /brainstorm 命令

## 命令用途

启动6阶段苏格拉底式需求探索流程，引导用户从模糊想法逐步探索到结构化设计文档。

## 命令描述

启动6阶段苏格拉底式需求探索流程，引导用户从模糊想法逐步探索到结构化设计文档。该命令通过逐个提问、方案对比、设计反思等结构化对话，确保需求完整、方案合理、设计可实施。

## 触发条件

| 触发方式 | 说明 |
|----------|------|
| 命令输入 | 用户输入 `/brainstorm` |
| 关键词触发 | 用户提及"需求探索"、"头脑风暴"、"brainstorm"、"苏格拉底" |
| 自动触发 | 检测到用户描述模糊需求时自动建议 |
| 条件触发 | 需求描述过于简略或缺乏细节时 |

## 命令名称与语法

```
/brainstorm <topic> [--depth=<深度>] [--output=<输出路径>]
```

## 参数定义

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `<topic>` | string | 是 | - | 探索主题或模糊需求描述 |
| `--depth` | enum | 否 | standard | 探索深度：quick/standard/thorough |
| `--output` | path | 否 | .agent_cache/<task>/ | 设计文档输出路径 |
| `--skip-reflect` | flag | 否 | false | 跳过Phase 4设计反思（不推荐） |
| `--auto-commit` | flag | 否 | true | 自动提交设计文档到设计分支 |

### 步骤详情

1. **Phase 1: Discovery（需求发现）** - 接收探索主题，扫描代码库，识别信息缺口，逐个提问
2. **Phase 2: Option Analysis（方案分析）** - 生成2-4个可行方案，Trade-off对比，等待用户选择
3. **Phase 3: Design Creation（设计创建）** - 生成结构化设计文档，用户确认
4. **Phase 4: Design Reflection（设计反思）** - 反向挑战设计，识别遗漏，修正设计文档
5. **Phase 5: Git Commit（设计提交）** - 保存设计文档，创建设计分支，提交
6. **Phase 6: Transition（交接过渡）** - 生成交接摘要，建议下一步操作

## 使用示例

### 示例1：标准探索

```
/brainstorm 实现用户认证系统
```

### 示例2：深度探索

```
/brainstorm 设计一个实时协作编辑器 --depth=thorough
```

### 示例3：指定输出路径

```
/brainstorm 添加支付功能 --output=./docs/designs/
```

### 示例4：快速探索

```
/brainstorm 优化首页加载速度 --depth=quick
```
