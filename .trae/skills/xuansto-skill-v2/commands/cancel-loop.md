# /cancel-loop 命令

## 命令用途

取消正在执行的自动循环（/loop），中止当前工作流并保存已完成的进度。

## MCP工具调用链

| 顺序 | MCP工具 | 参数 | 说明 |
|------|---------|------|------|
| 1 | workflow_dispatch | action=abort | 中止当前工作流 |

## 降级策略

| MCP工具 | 降级方式 | 降级脚本/操作 |
|---------|----------|---------------|
| workflow_dispatch | 内联执行 | 内联阶段推进（中止流程） |

## 涉及Agent

| Agent | 角色 | 职责 |
|-------|------|------|
| orchestrator | 主导 | 循环中止、进度保存 |

## 命令描述

取消正在执行的自动循环（/loop），中止当前工作流并保存已完成的进度。该命令确保循环取消时不会丢失已完成的工作。

## 触发条件

| 触发方式 | 说明 |
|----------|------|
| 命令输入 | 用户输入 `/cancel-loop` |
| 别名触发 | `/cancel`, `/stop` |
| 关键词触发 | 用户提及"取消循环"、"停止"、"cancel"、"abort" |
| 条件触发 | 检测到循环执行异常时 |

## 命令名称与语法

```
/cancel-loop [--save-progress] [--force]
```

## 参数定义

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `--save-progress` | flag | 否 | true | 保存已完成阶段的进度 |
| `--force` | flag | 否 | false | 强制取消（不等待当前阶段完成） |

## 执行流程

> 标准三步框架：1. 状态检查 → 2. 中止执行 → 3. 进度保存

1. **状态检查**：确认循环正在执行、确定当前阶段
2. **中止执行**：发送中止信号、等待当前操作完成（非强制模式）
3. **进度保存**：保存已完成阶段的产物、生成取消报告

## 质量门禁

| 门禁标识 | 阻塞级别(BLOCK/WARN) | 通过标准 |
|----------|----------------------|----------|
| CANCEL-CLEAN | BLOCK | 循环已完全停止、无残留进程 |

## 使用示例

### 示例1：正常取消

```
/cancel-loop
```

### 示例2：强制取消

```
/cancel-loop --force
```

### 示例3：不保存进度

```
/cancel-loop --save-progress=false
```
