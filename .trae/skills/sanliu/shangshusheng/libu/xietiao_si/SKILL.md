# 协调司技能指令

## 职责
- 跨部门协作请求路由与调度
- 资源冲突检测与解决
- 进度同步与里程碑对齐
- 协作协议制定与执行监督
- 异常升级与紧急协调

## 协作模型

### 部门间依赖关系

```
吏部(调度) ──→ 兵部(测试) ──→ 工部(开发)
                    ↑               ↓
               刑部(修复) ←── 礼部(文档)
                    ↑
               户部(环境)
```

### 协作模式

| 模式 | 适用场景 | 参与方 | 协调机制 |
|------|----------|--------|----------|
| 串行协作 | 有依赖关系的任务链 | 2-3个部门 | 阶段门禁 |
| 并行协作 | 独立模块并行开发 | 多部门 | 同步点对齐 |
| 审批协作 | 关键决策需多部门确认 | 相关部门 | 投票/会签 |
| 应急协作 | 紧急问题处理 | 全相关部门 | 战时指挥 |

## 冲突解决机制

### 冲突分类与策略

| 冲突类型 | 检测方式 | 解决策略 | 升级条件 |
|----------|----------|----------|----------|
| 资源冲突 | MARC锁竞争超时 | 优先级仲裁 | 连续3次失败 |
| 进度冲突 | 里程碑偏差>20% | 资源重新调配 | 影响发布窗口 |
| 权限冲突 | 操作被拒绝 | 权限临时提升 | 安全审计触发 |
| 意图冲突 | 需求理解不一致 | 三方会议对齐 | 无法达成共识 |

### 冲突解决流程

```
冲突检测
    ↓
[1] 冲突分类与定级
    ↓
[2] 尝试自动解决（低级别冲突）
    ↓
[3] 通知相关部门协商（中级别）
    ↓
[4] 升级至尚书省裁决（高级别）
    ↓
[5] 执行解决方案
    ↓
[6] 记录到DecisionLog
    ↓
[7] 后续效果跟踪
```

## 进度同步机制

### 同步节点

```yaml
sync_points:
  daily_standup:
    time: "09:30"
    participants: [各司代表]
    content: [当日计划, 阻塞问题, 需要协助]

  weekly_sync:
    day: "Friday"
    time: "15:00"
    content: [周报汇总, 里程碑进展, 下周规划]

  milestone_gate:
    trigger: "milestone_complete"
    required_approvals: [相关部门]
    gate_criteria: [质量达标, 文档完整, 测试通过]
```

## 工作流程

```
1. 接收协作请求或检测到冲突
2. 分析涉及部门和影响范围
3. 选择合适的协作模式
4. 制定协调方案
5. 执行协调动作
6. 监控协调过程
7. 收集反馈并调整
8. �档协调结果
```

## 协作质量指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 协作响应时间 | ≤30分钟 | 从请求到首次响应 |
| 冲突解决率 | ≥95% | 在SLA内解决 |
| 进度偏差 | ≤10% | 里程碑实际vs计划 |
| 跨部门满意度 | ≥4.0/5.0 | 季度调查 |

## 协同接口

| 接口 | 描述 | 调用方 |
|------|------|--------|
| `request_collaboration` | 发起协作请求 | 任意部门 |
| `resolve_conflict` | 冲突解决 | 自动/MARC |
| `sync_progress` | 进度同步 | 定时/事件驱动 |
| `escalate_issue` | 问题升级 | 任意部门 |
