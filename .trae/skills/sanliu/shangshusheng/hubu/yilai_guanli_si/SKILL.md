# 依赖管理司技能指令

## 职责
- 项目依赖声明与版本锁定
- 依赖漏洞扫描与告警
- 依赖更新策略制定与执行
- 兼容性冲突检测与解决
- 许可证合规检查

## 依赖生命周期

```
引入 → 版本锁定 → 漏洞监控 → 定期评估 → 安全更新 → 兼容验证 → 移除废弃
```

## 漏洞扫描策略

### 扫描频率与范围

| 扫描类型 | 频率 | 范围 | 响应级别 |
|----------|------|------|----------|
| 全量扫描 | 每日 | 所有直接+间接依赖 | Critical/High立即修复 |
| 增量扫描 | 每次PR | 变更的依赖子集 | 阻塞合并 |
| 按需扫描 | 手动触发 | 指定依赖/包 | 即时报告 |

### 漏洞等级处理

| 等级 | 定义 | SLA | 处理方式 |
|------|------|-----|----------|
| Critical | 可被利用的RCE/数据泄露 | 24h内 | 紧急修补 + 强制升级 |
| High | 权限提升/认证绕过 | 72h内 | 计划升级 + 缓解措施 |
| Medium | DoS/信息泄露 | 2周内 | 下版本纳入 |
| Low | 较低影响 | 下月版本 | 视情况处理 |

## 更新策略

### 语义化版本遵循

```yaml
update_policy:
  patch_updates:
    trigger: "automated"
    approval: "auto"
    risk_level: "low"
    examples: ["1.2.3 → 1.2.4"]

  minor_updates:
    trigger: "scheduled"
    approval: "ci_gate"
    risk_level: "medium"
    examples: ["1.2.3 → 1.3.0"]
    requires: [测试通过, 文档更新]

  major_updates:
    trigger: "manual"
    approval: "human_review"
    risk_level: "high"
    examples: ["1.2.3 → 2.0.0"]
    requires: [迁移计划, 回滚方案, 全面测试]
```

## 工作流程

```
1. 监控依赖变更事件（新增/更新/移除）
2. 执行漏洞扫描
3. 评估影响范围和风险
4. 制定更新方案
5. 在测试环境验证兼容性
6. 执行更新操作
7. 运行全量回归测试
8. 更新锁文件和CHANGELOG
9. 记录决策到DecisionLog
```

## 冲突解决

### 版本冲突场景

| 场景 | 原因 | 解决方式 |
|------|------|----------|
| 传递依赖冲突 | A依赖v1, B依赖v2 | 使用resolution策略指定 |
| Peer依赖不满足 | 缺少必需的同伴依赖 | 补充安装或降级 |
| 循环依赖 | A→B→A | 重构消除循环 |
| 平台不兼容 | 包不支持当前平台 | 寻找替代或条件安装 |

## 依赖健康指标

| 指标 | 目标值 | 说明 |
|------|--------|------|
| 漏洞覆盖率 | 100% | 所有依赖均被扫描 |
| Critical/High漏洞数 | 0 | 零容忍 |
| 过期依赖比例 | <10% | 超过6个月未更新的依赖 |
| 许可证合规率 | 100% | 符合项目许可证政策 |

| 接口 | 描述 | 调用方 |
|------|------|--------|

| `check_license` | 许可证检查 | 发布前门禁 |
