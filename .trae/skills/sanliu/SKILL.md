## 🚀 快速开始

**环境准备**：
```bash
# 启动核心服务
python skillscripts/core/start_services.py

# 检查健康状态（含四维防线状态）
python skillscripts/core/health_check.py

# 初始化MARC资源协调器
python skillscripts/core/resource_coordinator.py --init

# 启动Decision Log服务
python skillscripts/core/decision_log.py --start
```

**启动开发流程**：
```bash
# 基本用法
/skill sanliu <项目需求描述>

# 完整示例（含技术栈和TDD模式）
/skill sanliu 开发一个博客系统 --tech-stack Python+Vue+PostgreSQL --tdd-mode strict

# 使用四维防线保护模式
/skill sanliu 开发用户认证模块 --defense-mode full --priority manual

# 多Agent协作模式
/skill sanliu 进行全栈代码审查 --agency-mode enabled --agents code-reviewer,security-engineer

# UI/UX协同模式
/skill sanliu 设计电商首页 --ux-collaboration deep --design-system material
```

**基本流程**：
```
提供需求 → [中书省] 分析+SDD规范 → [门下省] 审议（含安全审计） → [尚书省] 执行TDD循环（受四维防线保护） → [MARC] 资源协调 → [Agency Bridge] 外部Agent协作 → [Decision Log] 记录决策 → 持续跟踪与自演化
```

## 🛡️ 四维度输出防线系统（v4.0核心）

### 概述

四维度输出防线（Four-Dimensional Defense, 4DD）是v4.0的核心创新，通过**四层纵深防御**确保每次输出的质量、安全性和可靠性。这是Sanliu技能从"流程管理"升级为"质量保障"的关键里程碑。

### 防线架构

```
┌─────────────────────────────────────────────────────────────┐
│                   四维度输出防线系统 (4DD)                      │
├─────────────────────────────────────────────────────────────┤

│  ┌──────────────────────────────────────────────────────┐   │
│  │  第1层: PromptLayer (Prompt工程层)                     │   │
│  │  ├─ 意图识别与分类 (6种意图类型)                        │   │
│  │  ├─ 上下文自动注入 (项目信息/会话信息)                  │   │
│  │  ├─ 歧义消解与确认 (模糊术语检测)                       │   │
│  │  └─ 输入验证与标准化 (危险命令拦截)                     │   │
│  └────────────────────┬─────────────────────────────────┘   │

│  ┌──────────────────────────────────────────────────────┐   │

│  └────────────────────┬─────────────────────────────────┘   │

│  │  ├─ 编码规范检查 (行长度/命名/缩进/复杂度)             │   │

│  │  ├─ 自动回滚状态准备                                   │   │
│  │  ├─ 降级策略选择 (简化/人工介入/重试/缓存)            │   │
│  │  └─ 错误日志记录与根因分析                              │   │

└─────────────────────────────────────────────────────────────┘
```

### 各层详细能力

#### 第1层：Prompt工程层（PromptLayer）

| 功能 | 说明 | 检测项数 |
|------|------|----------|
| **意图识别** | 6种意图类型自动分类 | 12+ 正则模式 |
| **上下文注入** | 项目信息/会话信息/意图特定上下文 | 4类上下文模板 |
| **歧义消解** | 模糊术语检测、多问题识别 | 15+ 歧义指示词 |
| **输入验证** | 长度限制、危险命令检测 | 10+ 危险模式 |

#### 第2层：能力约束层（CapabilityLayer）

```
  │  特点: 高效率、一致性保证、可追溯          │
  ├─────────────────────────────────────────┤
  │  Level 3: COMMAND (命令操作)             │  ← 最低优先级
  │  适用: 环境配置、依赖安装、构建部署        │
```

## 📊 持续质量监控体系（v3.2.0增强，v4.0集成四维防线）

### 概述

持续质量监控体系在v4.0中与**四维防线**深度集成，实现从实时监控到主动防护的升级。

### 监控维度（6维）

#### 1. 实时代码质量监控
- **质量指标收集**：自动采集圈复杂度、代码重复率、代码异味等指标
- **趋势分析**：识别质量变化趋势，预测潜在风险
- **基线对比**：与历史基线对比，量化改进效果

#### 2. 测试覆盖监控
- **覆盖率追踪**：实时跟踪行覆盖率、分支覆盖率、函数覆盖率
- **覆盖缺口分析**：识别未覆盖的关键路径和边界条件
- **覆盖目标管理**：设定和追踪覆盖率目标

#### 3. 技术债务监控
- **债务识别**：自动识别技术债务（代码异味、过时依赖等）
- **债务量化**：评估技术债务的影响程度和修复成本
- **债务追踪**：持续跟踪技术债务的变化趋势

#### 4. 性能基准监控
- **性能指标采集**：响应时间、吞吐量、资源利用率
- **性能回归检测**：自动检测性能退化
- **瓶颈定位**：辅助定位性能瓶颈

#### 5. 安全合规监控（v3.3.0新增）
- **OWASP Top 10检查**：常见Web安全漏洞检测
- **依赖漏洞扫描**：第三方依赖安全性检查
- **权限验证**：访问控制和权限合规性

#### 6. 文档质量监控（v3.3.0新增）
- **格式合规性**：Markdown/代码注释格式检查
- **编码正确性**：UTF-8编码、字符集验证
- **链接有效性**：内部/外部链接可达性检查

## 📋 YAML工作流DSL引擎（v4.0新增）

### 概述

YAML工作流DSL引擎是v4.0引入的工作流定义和执行引擎，允许使用YAML格式声明式地定义复杂的开发工作流。

### DSL语法示例

```yaml
name: user-auth-development
version: "4.0"
description: 用户认证模块开发工作流

triggers:
  - type: manual
  - type: webhook
    event: pr_opened

steps:
  - id: four_d_defense
    name: 四维防线检查
    uses: core/four_d_defense
    with:
      input: "${{ payload.requirement }}"
      mode: full

  - id: marc_allocate
    name: MARC资源分配
    uses: core/resource_coordinator
    with:
      resources:
        - type: file
          path: src/auth/
          lock_type: exclusive
      agent_quota:
        max_files_locked: 5

  - id: agency_consult
    name: Agency Agent咨询
    if: ${{ steps.four_d_defense.outputs.confidence < 0.8 }}
    uses: integration/agency_bridge
    with:
      agents:
        - security-engineer
        - code-reviewer
      task: "安全审计与代码审查"

  - id: tdd_cycle
    name: TDD开发循环
    uses: pipeline/sdd_tdd_fusion_engine
    with:
      spec: docs/specs/auth_spec.md
      tdd_mode: strict
      extract_executable_clauses: true

  - id: decision_record
    name: 记录关键决策
    uses: core/decision_log
    with:
      maker: "尚书省-工部-虞衡司"
      content: "技术选型决策"
      risk: medium

outputs:
  quality_score: ${{ steps.four_d_defense.outputs.score }}
  test_coverage: ${{ steps.tdd_cycle.outputs.coverage }}
  decision_id: ${{ steps.decision_record.outputs.decision_id }}
```

### 使用示例

```bash
# 执行YAML工作流
python skillscripts/core/workflow_dsl_engine.py \
  --workflow workflows/user-auth.yml \
  --payload '{"requirement": "实现OAuth2.0登录"}'

# 验证工作流语法
python skillscripts/core/workflow_dsl_engine.py \
  --validate workflows/user-auth.yml

# 列出可用步骤
python skillscripts/core/workflow_dsl_engine.py --list-steps
```

## 🤝 贡献指南

欢迎贡献！请遵循 TDD 开发流程，保持测试覆盖率 > 80%，遵循代码规范（PEP8 for Python, ESLint for JavaScript）。

**v4.0贡献注意事项**：
- 新功能需通过四维防线检查
- 重要决策需记录到Decision Log
- 代码变更需遵循操作优先级（MANUAL > SCRIPT > COMMAND）
- 涉及多Agent协作需使用MARC资源协调
