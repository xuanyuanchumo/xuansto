# 规范验证子技能

## 概述
规范验证子技能用于验证实现是否符合规范定义，通过一致性检查和覆盖率计算，确保代码实现与规范文档保持同步。

## 调用时机
- 规范文档更新后验证现有实现
- 新功能开发完成后验证合规性
- 代码审查时检查规范遵循情况
- 项目里程碑验收时评估规范覆盖率

## 规范验证流程

### 验证流程概述
1. 解析规范文档，提取验证点
2. 分析实现代码，识别实现元素
3. 执行一致性检查规则
4. 计算规范覆盖率
5. 生成验证报告

## 规范覆盖率计算方法

### 覆盖率计算公式

#### 1. 实体覆盖率
```
实体覆盖率 = (已实现的规范实体数 / 规范定义的总实体数) × 100%
```

实体包括：
- 数据模型/实体类
- 服务/组件
- 接口/端点
- 工具/函数

#### 2. 接口覆盖率
```
接口覆盖率 = (已实现的规范接口数 / 规范定义的总接口数) × 100%
```

接口包括：
- 公共 API
- 内部接口
- 回调接口
- 事件接口

#### 3. 规则覆盖率
```
规则覆盖率 = (已实现的业务规则数 / 规范定义的总业务规则数) × 100%
```

规则包括：
- 验证规则
- 计算规则
- 转换规则
- 流程规则

#### 4. 约束覆盖率
```
约束覆盖率 = (已满足的约束数 / 规范定义的总约束数) × 100%
```

约束包括：
- 数据约束
- 安全约束
- 性能约束
- 兼容性约束

### 综合覆盖率计算

```
综合覆盖率 = Σ(覆盖率类型 × 权重)

权重分配：
- 实体覆盖率：30%
- 接口覆盖率：30%
- 规则覆盖率：25%
- 约束覆盖率：15%
```

### 覆盖率等级划分

| 等级 | 覆盖率范围 | 说明 |
|------|-----------|------|
| A | 90% - 100% | 优秀，规范覆盖完整 |
| B | 75% - 89% | 良好，主要规范已覆盖 |
| C | 60% - 74% | 合格，核心规范已覆盖 |
| D | 40% - 59% | 待改进，部分规范未覆盖 |
| E | 0% - 39% | 不合格，大量规范未覆盖 |

## 验证示例

### 示例：用户管理模块规范验证

#### 规范定义
```yaml
实体：
  - User: 用户实体
    字段：id, name, email, status
接口：
  - createUser: 创建用户
  - getUser: 获取用户
  - updateUser: 更新用户
  - deleteUser: 删除用户
规则：
  - 邮箱格式验证
  - 用户名唯一性检查
约束：
  - 用户状态枚举值
  - 密码最小长度
```

#### 验证结果
```
实体覆盖率：100% (1/1)
接口覆盖率：75% (3/4) - deleteUser 未实现
规则覆盖率：50% (1/2) - 用户名唯一性检查未实现
约束覆盖率：50% (1/2) - 密码长度约束未验证

综合覆盖率：68.75% (等级 C)
```

#### 一致性问题
1. User 实体缺少 status 字段
2. getUser 接口返回值与规范不一致
3. 邮箱格式验证规则实现不完整
