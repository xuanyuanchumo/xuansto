# 项目规划流程

## 项目计划制定流程

### 需求收集和分析
1. **需求来源识别**：从需求规格说明书（SRS）提取项目需求
2. **需求分类整理**：按功能模块、优先级、复杂度分类
3. **需求澄清确认**：与利益相关者确认需求细节
4. **需求变更管理**：建立需求变更追踪机制

### 范围定义
1. **项目边界划定**：明确项目包含和不包含的内容
2. **可交付成果清单**：列出所有预期交付物
3. **假设与约束**：记录项目假设条件和约束限制
4. **范围基准建立**：经审批后作为范围管理基准

### 时间估算
1. **专家判断法**：基于历史经验和专家意见估算
2. **类比估算法**：参考类似项目的历史数据
3. **参数估算法**：使用量化模型计算工期
4. **三点估算法**：计算乐观、悲观、最可能时间的加权平均
5. **预留时间**：为风险和不确定性预留缓冲时间

### 资源分配
1. **资源需求清单**：列出所需资源类型和数量
2. **资源可用性分析**：评估资源获取可行性
3. **资源平衡优化**：解决资源冲突和过度分配
4. **资源日历制定**：明确资源可用时间窗口

## 任务分解方法

### WBS（工作分解结构）方法
1. **分解原则**
   - 100%原则：子任务完全覆盖父任务范围
   - 相互独立：同级任务之间不重叠
   - 完全穷尽：所有工作内容都包含在内

2. **分解步骤**
   - 识别项目主要可交付成果
   - 按阶段或组件进行一级分解
   - 逐层细化至可管理的工作包
   - 分解深度：工作包工时 8-80 小时为宜

3. **WBS 编码体系**
   - 采用层级编码（如 1.1.1）
   - 便于任务追踪和报告
   - 支持任务汇总统计

### 任务粒度控制
1. **粒度标准**
   - 可估算：任务工期可合理估算
   - 可分配：任务可明确分配给责任人
   - 可度量：任务完成标准清晰可测
   - 可控制：任务执行过程可监控

2. **粒度调整原则**
   - 复杂任务进一步拆分
   - 简单任务适当合并
   - 保持任务间粒度相对均衡
   - 避免过度细化导致管理成本增加

### 任务依赖识别
1. **依赖类型**
   - 完成-开始（FS）：前置任务完成后，后置任务开始
   - 开始-开始（SS）：前置任务开始后，后置任务开始
   - 完成-完成（FF）：前置任务完成后，后置任务完成
   - 开始-完成（SF）：前置任务开始后，后置任务完成

2. **依赖分析步骤**
   - 识别任务间逻辑关系
   - 确定硬依赖（技术/逻辑约束）
   - 识别软依赖（资源/偏好约束）
   - 绘制网络图或甘特图
   - 计算关键路径

3. **依赖管理**
   - 最小化任务间耦合
   - 识别并管理外部依赖
   - 建立依赖变更通知机制

## 资源需求评估方法

### 人力资源评估
1. **角色定义**：明确项目所需角色和职责
2. **技能矩阵**：评估团队成员技能匹配度
3. **工作量计算**：
   - 人天 = 任务工时 ÷ 每日工作时间
   - 考虑效率系数（通常 0.6-0.8）
4. **团队规模估算**：基于工作量和时间约束计算
5. **培训需求**：识别技能差距和培训计划

### 技术资源评估
1. **开发环境**：IDE、版本控制、CI/CD 工具
2. **基础设施**：服务器、存储、网络带宽
3. **第三方服务**：云服务、API、许可证
4. **开发工具**：测试工具、监控工具、文档工具
5. **预算估算**：按资源类型和用量计算成本

### 时间资源评估
1. **工期估算方法**
   - 工作量 ÷ 资源数量 = 工期
   - 考虑学习曲线和沟通开销
   - 识别并行任务优化工期

2. **时间约束分析**
   - 硬性截止日期
   - 里程碑时间点
   - 资源可用时间窗口

3. **进度缓冲策略**
   - 关键链法：在关键路径末端设置缓冲
   - 风险储备：为高风险任务预留时间
   - 管理储备：应对未知风险的应急时间

## 里程碑定义方法

### 里程碑识别
1. **里程碑特征**
   - 零工期：表示时间节点而非任务
   - 重要节点：标志项目重要进展
   - 可验证：有明确的完成标志

2. **常见里程碑类型**
   - 阶段完成里程碑：需求确认、设计完成、开发完成
   - 交付里程碑：版本发布、系统上线
   - 决策里程碑：方案评审、验收审批
   - 外部里程碑：客户验收、合同节点

3. **里程碑识别步骤**
   - 回顾项目可交付成果
   - 识别关键决策点
   - 确定阶段边界
   - 与利益相关者确认

### 里程碑验收标准
1. **验收标准要素**
   - 可交付成果清单
   - 质量检查项
   - 文档交付要求
   - 审批签字要求

2. **验收标准制定原则**
   - SMART 原则：具体、可衡量、可达成、相关、有时限
   - 可测试性：标准可通过测试或检查验证
   - 无歧义：表述清晰，理解一致

3. **验收标准示例**
   - 需求确认：SRS 文档经评审签字，用例覆盖率 100%
   - 设计完成：设计文档评审通过，技术方案经批准
   - 开发完成：代码审查通过，单元测试覆盖率 ≥ 80%
   - 测试完成：测试用例执行率 100%，严重缺陷清零

### 里程碑时间线
1. **时间线规划步骤**
   - 确定项目起止日期
   - 根据任务依赖关系排列里程碑
   - 分配里程碑时间窗口
   - 识别关键路径里程碑

2. **里程碑间隔原则**
   - 间隔适中：便于进度监控和风险预警
   - 节奏合理：避免里程碑过于密集或稀疏
   - 与迭代周期对齐：敏捷项目与迭代周期配合

3. **里程碑可视化**
   - 甘特图：展示里程碑在时间轴上的位置
   - 里程碑图：突出显示关键里程碑
   - 燃尽图：跟踪里程碑完成进度

## 与六部协调

### 中书省 - 计划制定
- 负责整体项目计划编制
- 协调各司资源需求
- 制定项目进度基准
- 输出项目计划文档

### 门下省 - 计划评审
- 审核计划可行性
- 评估资源合理性
- 检查风险应对措施
- 把控计划质量关口

### 户部 - 资源协调
- 人力资源调配支持
- 预算审批和分配
- 成本效益分析
- 资源冲突协调

### 工部各司 - 任务执行
- **营缮司**：前端开发任务分解和估算
- **虞衡司**：后端开发任务分解和估算
- **都水司**：数据相关任务分解和估算
- **屯田司**：基础设施任务分解和估算

## 输出物
- 项目计划书
- WBS 分解结构
- 甘特图/网络图
- 资源需求清单
- 里程碑清单
