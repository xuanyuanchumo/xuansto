# 透明度验证子技能

## 概述
透明度验证子技能用于验证开发过程中的透明度要求是否满足，确保决策过程、输入输出、代码变更等关键信息可追溯。

## 调用时机
- 门下省审议方案时
- 项目里程碑验收时
- 用户请求透明度审计时

## 验证标准

### 1. 决策日志完整性
- [ ] 关键决策是否都有决策日志
- [ ] 决策依据是否充分
- [ ] 推理过程是否清晰
- [ ] 备选方案是否记录

### 2. 输入输出可追溯性
- [ ] 技能调用的输入是否完整记录
- [ ] 技能调用的输出是否完整记录
- [ ] 数据流转是否可追溯
- [ ] 输入来源是否明确

### 3. 代码变更可解释性
- [ ] 代码变更是否都有详细记录
- [ ] 变更原因是否明确
- [ ] 变更影响是否评估
- [ ] diff 格式是否正确

### 4. 中间产物完整性
- [ ] 设计文档是否存档
- [ ] 测试用例是否存档
- [ ] 重构记录是否存档

### 5. 推理过程清晰度
- [ ] 需求分析推理是否记录
- [ ] 代码生成推理是否记录
- [ ] 问题诊断推理是否记录

## 验证流程

1. 收集待验证的技能调用记录
2. 检查决策日志完整性
3. 检查输入输出追踪
4. 检查代码变更记录
5. 检查中间产物存档
6. 生成透明度评分报告

## 透明度评分

| 维度 | 权重 | 评分标准 |
|------|------|----------|
| 决策日志 | 25% | 完整性 × 准确性 |
| 输入输出 | 25% | 完整性 × 可追溯性 |
| 代码变更 | 20% | 详细度 × 可解释性 |
| 中间产物 | 15% | 完整性 × 组织性 |
| 推理过程 | 15% | 清晰度 × 逻辑性 |

总分 = Σ(维度得分 × 权重)

## 输出物
- 透明度验证报告
- 问题清单
- 改进建议

## 与门下省协作
透明度验证是门下省审议的重要组成部分，验证结果直接影响审议结论。
