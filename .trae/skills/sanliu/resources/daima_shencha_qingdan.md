# 代码审查清单

## 代码正确性
- [ ] 代码是否实现了需求功能？
- [ ] 是否有明显的逻辑错误？
- [ ] 边界条件是否处理正确？
- [ ] 异常情况是否考虑周全？
- [ ] 是否有内存泄漏风险？

## 代码质量
- [ ] 命名是否清晰、有意义？
- [ ] 函数/方法长度是否合理（<50行）？
- [ ] 参数数量是否合理（<5个）？
- [ ] 是否有重复代码？
- [ ] 复杂度是否在可接受范围？

## 代码风格
- [ ] 是否符合项目编码规范？
- [ ] 缩进和格式是否一致？
- [ ] 注释是否恰当？
- [ ] 是否有注释掉的代码？

## 测试覆盖
- [ ] 是否有对应的单元测试？
- [ ] 测试覆盖率是否达标？
- [ ] 边界条件是否有测试？
- [ ] 异常情况是否有测试？

## 安全性
- [ ] 输入是否经过验证？
- [ ] 是否有SQL注入风险？
- [ ] 是否有XSS风险？
- [ ] 敏感数据是否加密？
- [ ] 权限检查是否完整？

## 性能
- [ ] 是否有明显的性能问题？
- [ ] 数据库查询是否优化？
- [ ] 是否有不必要的循环？
- [ ] 缓存策略是否合理？

## 可维护性
- [ ] 代码是否易于理解？
- [ ] 是否有足够的文档？
- [ ] 依赖关系是否清晰？
- [ ] 是否易于扩展？

## 兼容性
- [ ] 是否向后兼容？
- [ ] 是否考虑跨平台？
- [ ] 是否考虑不同版本？

## 代码审查流程

```
1. 提交审查
   - 创建Pull Request / Merge Request
   - 填写PR描述（改动内容、测试情况）
   - 关联相关Issue

2. 自动检查
   - CI构建通过
   - 代码风格检查通过
   - 测试覆盖率达标

3. 人工审查
   - 至少1-2人审查
   - 使用审查清单逐项检查
   - 提出修改建议

4. 修改完善
   - 作者根据建议修改
   - 重新触发审查

5. 审查通过
   - 审查者Approve
   - 合并到目标分支
   - 关闭相关Issue
```

## 审查意见模板

```
【必须修改】
- [文件:行号] 问题描述
  原因: 为什么需要修改
  建议: 如何修改

【建议修改】
- [文件:行号] 问题描述
  原因: 为什么建议修改
  建议: 如何修改

【疑问】
- [文件:行号] 疑问内容
  背景: 为什么有这个疑问

【优点】
- 代码中的亮点
```
