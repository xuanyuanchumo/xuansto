| 异味名称 | 描述 | 检测方法 | 重构建议 |
|----------|------|----------|----------|

## 架构异味检测方法

### 单一职责原则违反检测

```
1. 分析类的公共方法，识别职责数量
2. 检查类的字段是否被不同方法组使用
3. 评估类的变更原因是否唯一
4. 检查类名是否能准确描述所有方法
```

### 开放封闭原则违反检测

```
1. 检查新增功能时是否修改现有代码
2. 分析条件分支是否频繁增加
3. 检查是否使用if-else或switch处理不同类型
4. 评估扩展机制是否完善
```

### 依赖倒置原则违反检测

```
1. 检查高层模块是否直接依赖低层具体类
2. 分析依赖是否指向抽象而非具体实现
3. 检查是否存在硬编码的依赖创建
4. 评估依赖注入的使用情况
```

### 高耦合度检测

```
1. 分析类的传入耦合(Ca)和传出耦合(Ce)
2. 检查模块间的依赖数量
3. 分析修改一个类时的影响范围
4. 检查是否存在循环依赖
```

## 异味检测工具配置

```yaml
code_smell_detection:
  tools:
    - name: "SonarQube"
      rules:
        - "cognitive_complexity"
        - "duplicated_lines"
        - "code_smells"
    - name: "ESLint"
      rules:
        - "complexity"
        - "max-lines"
        - "max-params"
    - name: "Pylint"
      rules:
        - "R0913"  # too-many-arguments
        - "R0914"  # too-many-locals
        - "R0915"  # too-many-statements
        
  thresholds:
    cyclomatic_complexity: 10
    cognitive_complexity: 15
    lines_of_code_per_function: 50
    parameters_per_function: 5
    nesting_depth: 4
```

## 高内聚低耦合评估

### 内聚度评估指标

| 指标 | 低内聚表现 | 高内聚表现 | 评估方法 |
|------|-----------|-----------|----------|
| 方法关联性 | 方法间无关联 | 方法共同完成单一职责 | 方法调用分析 |
| 字段使用率 | 方法使用不同字段 | 方法共享核心字段 | 字段访问统计 |
| 职责数量 | 多个不相关职责 | 单一明确职责 | 职责分析 |
| 命名准确性 | 难以用一词描述 | 名称清晰准确 | 命名审查 |

### 耦合度评估指标

| 指标 | 紧耦合表现 | 松耦合表现 | 评估方法 |
|------|-----------|-----------|----------|
| 依赖方式 | 依赖具体类 | 依赖接口/抽象 | 依赖分析 |
| 数据传递 | 传递大量数据 | 传递必要数据 | 参数分析 |
| 调用方式 | 直接调用内部方法 | 通过公共接口调用 | 调用链分析 |
| 变更影响 | 修改影响多个模块 | 修改影响范围小 | 影响范围分析 |
