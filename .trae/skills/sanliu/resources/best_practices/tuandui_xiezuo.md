# 团队协作最佳实践指南

## 概述

三省六部技能的核心优势在于高效的团队协作机制。本文档提供 Agent 分配、任务拆分和代码审查的最佳实践，帮助团队在复杂项目中实现高效协同。

## Agent 分配最佳实践

### Agent 分配原则

#### 原则1：能力匹配原则

```
任务需求分析 ──▶ Agent能力评估 ──▶ 最佳匹配选择

示例：
任务：实现用户认证模块
需求能力：
- 后端开发能力
- 安全知识
- 测试能力

匹配 Agent：
- 工部 Agent（后端开发）
- 兵部 Agent（安全测试）
- 刑部 Agent（安全审查）
```

#### 原则2：负载均衡原则

```
┌─────────────────────────────────────────────────────────────────┐
│                    Agent 负载监控                                │
│                                                                  │
│   Agent ID   │  当前任务数  │  负载率  │  状态                   │
│──────────────┼──────────────┼──────────┼────────────────────────│
│   Agent-001  │      2       │   40%    │  🟢 可分配              │
│   Agent-002  │      4       │   80%    │  🟡 接近满载            │
│   Agent-003  │      5       │  100%    │  🔴 满载，不可分配       │
│   Agent-004  │      0       │    0%    │  🟢 空闲，优先分配       │
│                                                                  │
│   分配策略：优先选择负载率低的 Agent                              │
└─────────────────────────────────────────────────────────────────┘
```

#### 原则3：协作效率原则

```
协作效率评估维度：
1. 沟通成本：Agent 之间的沟通频率和效率
2. 依赖关系：任务之间的依赖和协作需求
3. 历史协作：Agent 之间的历史协作记录

优先分配策略：
- 有成功协作历史的 Agent 组合
- 沟通成本低的 Agent 组合
- 技能互补的 Agent 组合
```

### Agent 分配流程

#### 详细步骤

**步骤1：任务分析**
1. 解析任务需求
2. 识别所需技能
3. 确定任务优先级
4. 评估任务复杂度

**步骤2：Agent 筛选**
1. 查询可用 Agent 列表
2. 过滤具备所需技能的 Agent
3. 排除负载过高的 Agent
4. 按匹配度排序

**步骤3：最优分配**
1. 选择最佳匹配 Agent
2. 考虑协作效率因素
3. 执行分配操作
4. 记录分配决策

**步骤4：分配验证**
1. 确认 Agent 接受任务
2. 监控任务执行状态
3. 必要时调整分配

#### 示例：用户认证模块 Agent 分配

```python
# scripts/assign_agent.py 使用示例

# 分配工部 Agent 负责后端开发
python scripts/assign_agent.py \

# 分配兵部 Agent 负责测试
python scripts/assign_agent.py \
    --role "兵部-测试工程师" \

    --skills "pytest,安全测试,边界测试" \
    --priority high \
    --call_id "AUTH-002"

# 分配刑部 Agent 负责代码审查
python scripts/assign_agent.py \
    --role "刑部-代码审查员" \
    --task "审查用户认证模块代码质量" \
    --skills "安全审查,代码规范,重构" \
    --priority medium \
    --call_id "AUTH-003"
```

### Agent 分配注意事项

1. **避免过度分配**
   - 单个 Agent 同时任务数不超过 5 个
   - 留出缓冲时间应对紧急任务
   - 定期检查 Agent 负载情况

2. **考虑时区因素**
   - 分布式团队注意时区差异
   - 协作任务安排在工作时间重叠段
   - 异步任务可跨时区分配

3. **技能培训支持**
   - 新技能需求提前安排培训
   - 提供 Agent 技能提升路径
   - 建立技能知识库

#### 任务粒度标准

| 粒度等级 | 工时范围 | 适用场景 | 分配策略 |
|----------|----------|----------|----------|
| 粗粒度 | > 40小时 | 项目阶段、里程碑 | 分配给尚书省协调 |
| 中粒度 | 8-40小时 | 功能模块、子系统 | 分配给六部负责人 |
| 细粒度 | 2-8小时 | 具体功能点、任务 | 分配给具体 Agent |
| 微粒度 | < 2小时 | 小修改、配置调整 | 合并或快速处理 |

### 任务拆分详细步骤

#### 步骤1：识别主要交付物

1. **分析项目范围**
   - 回顾需求规格说明书
   - 识别主要功能模块
   - 确定可交付成果清单

2. **定义一级任务**
   - 按功能模块划分
   - 按开发阶段划分
   - 按技术层次划分

#### 步骤2：逐层细化分解

1. **二级任务分解**
   - 将一级任务拆分为子任务
   - 确保子任务完全覆盖父任务
   - 子任务之间相互独立

2. **三级任务分解**
   - 细化到可分配的工作包
   - 每个工作包有明确交付物
   - 工作包可独立测试验证

#### 步骤3：定义任务属性

1. **基本属性**
   - 任务ID：唯一标识符
   - 任务名称：简洁明确的描述
   - 任务描述：详细说明和要求
   - 优先级：高/中/低

2. **执行属性**
   - 预估工时：完成所需时间
   - 负责Agent：任务分配对象
   - 开始时间：计划开始日期
   - 截止时间：计划完成日期

3. **依赖属性**
   - 前置任务：依赖的任务ID
   - 后置任务：被依赖的任务ID
   - 外部依赖：外部系统或资源

#### 步骤4：建立任务关系

1. **依赖类型识别**
   - FS（完成-开始）：A完成后B才能开始
   - SS（开始-开始）：A开始后B才能开始
   - FF（完成-完成）：A完成后B才能完成
   - SF（开始-完成）：A开始后B才能完成

2. **关键路径分析**
   - 绘制任务网络图
   - 计算关键路径
   - 识别关键任务

### 任务拆分注意事项

1. **避免过度拆分**
   - 任务粒度适中，管理成本可控
   - 过细的任务增加协调开销
   - 保持任务完整性

2. **考虑并行性**
   - 识别可并行执行的任务
   - 减少不必要的依赖关系
   - 缩短项目总工期

3. **预留缓冲时间**
   - 为高风险任务预留缓冲
   - 考虑学习曲线时间
   - 应对需求变更

## 代码审查最佳实践

### 代码审查内容

#### 1. 代码规范审查

| 审查项 | 检查内容 | 工具支持 |
|--------|----------|----------|
| 命名规范 | 变量、函数、类命名是否清晰 | ESLint, Pylint |
| 代码格式 | 缩进、空格、换行是否统一 | Prettier, Black |
| 注释规范 | 注释是否清晰、必要 | 人工审查 |
| 文档规范 | 函数文档、模块文档是否完整 | 人工审查 |

#### 2. 代码质量审查

| 审查项 | 检查内容 | 关注点 |
|--------|----------|--------|
| 可读性 | 代码逻辑是否清晰 | 复杂度、嵌套层次 |
| 可维护性 | 代码是否易于修改 | 模块化、解耦程度 |
| 可测试性 | 代码是否易于测试 | 依赖注入、纯函数 |
| 性能 | 是否存在性能问题 | 算法复杂度、资源使用 |

#### 3. 安全性审查

| 审查项 | 检查内容 | 风险等级 |
|--------|----------|----------|
| 输入验证 | 用户输入是否验证和过滤 | 高 |
| SQL注入 | 数据库查询是否使用参数化 | 高 |
| XSS攻击 | 输出是否转义处理 | 高 |
| 敏感信息 | 密码、密钥是否安全处理 | 高 |
| 权限控制 | 访问权限是否正确检查 | 中 |

#### 4. 测试覆盖审查

| 审查项 | 检查内容 | 标准 |
|--------|----------|------|
| 单元测试 | 是否编写单元测试 | 覆盖率 ≥ 80% |
| 边界测试 | 是否测试边界条件 | 覆盖关键边界 |
| 异常测试 | 是否测试异常路径 | 覆盖主要异常 |
| 集成测试 | 是否编写集成测试 | 覆盖关键流程 |
