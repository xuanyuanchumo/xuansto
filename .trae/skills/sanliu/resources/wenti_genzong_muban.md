# 问题跟踪模板

## 问题生命周期

```
新建 → 确认 → 分配 → 进行中 → 已解决 → 已验证 → 已关闭
  │       │       │        │         │         │
  └───────┴───────┴────────┴─────────┴─────────┘
                    ↓ 可回退到任意前一状态
```

## 问题状态定义

| 状态 | 描述 | 操作权限 |
|------|------|----------|
| 新建 | 问题刚创建，待确认 | 所有人可创建 |
| 确认 | 问题已确认有效 | 项目成员 |
| 分配 | 问题已分配给处理人 | 项目管理员 |
| 进行中 | 正在处理中 | 指派处理人 |
| 已解决 | 问题已修复，待验证 | 指派处理人 |
| 已验证 | 验证通过，待关闭 | 测试人员 |
| 已关闭 | 问题处理完成 | 项目管理员 |
| 重新打开 | 验证失败，重新处理 | 测试人员 |

## 问题优先级定义

| 优先级 | 描述 | 响应时间 | 解决时间 |
|--------|------|----------|----------|
| P0-紧急 | 系统崩溃/数据丢失/安全漏洞 | 15分钟 | 4小时 |
| P1-高 | 核心功能不可用 | 1小时 | 24小时 |
| P2-中 | 重要功能受损 | 4小时 | 3天 |
| P3-低 | 次要功能问题 | 1天 | 1周 |
| P4-建议 | 优化建议 | 1周 | 版本规划 |

## 问题分类

```
按类型分类:
  - Bug: 功能缺陷
  - 缺陷: 非功能性问题
  - 安全漏洞: 安全相关问题
  - 性能问题: 性能相关
  - 文档问题: 文档错误或缺失

按模块分类:
  - 前端
  - 后端
  - 数据库
  - 接口
  - 基础设施

按严重程度分类:
  - 致命: 系统完全不可用
  - 严重: 核心功能不可用
  - 一般: 功能受损但有替代方案
  - 轻微: 小问题，不影响使用
  - 建议: 改进建议
```

## 问题跟踪模板

```yaml
issue:
  id: "ISSUE-XXX"
  title: "问题标题"
  
  basic_info:
    type: "Bug|缺陷|安全漏洞|性能问题|文档问题"
    priority: "P0|P1|P2|P3|P4"
    severity: "致命|严重|一般|轻微|建议"
    status: "新建|确认|分配|进行中|已解决|已验证|已关闭"
    
  assignment:
    reporter: "报告人"
    assignee: "处理人"
    verifier: "验证人"
    
  description:
    summary: "问题简要描述"
    steps_to_reproduce:
      - "步骤1"
      - "步骤2"
      - "步骤3"
    expected_result: "预期结果"
    actual_result: "实际结果"
    
  environment:
    os: "操作系统"
    browser: "浏览器版本"
    version: "软件版本"
    
  attachments:
    - "截图"
    - "日志"
    - "复现视频"
    
  timeline:
    created_at: "创建时间"
    confirmed_at: "确认时间"
    assigned_at: "分配时间"
    resolved_at: "解决时间"
    verified_at: "验证时间"
    closed_at: "关闭时间"
    
  resolution:
    root_cause: "根本原因"
    solution: "解决方案"
    affected_files: ["文件列表"]

  comments:
    - author: "评论人"
      content: "评论内容"
      time: "评论时间"
```

## 问题跟踪流程

```
1. 问题报告
   - 填写问题模板
   - 提供复现步骤
   - 附上相关材料

2. 问题确认
   - 验证问题是否存在
   - 评估问题优先级
   - 确认问题分类

3. 问题分配
   - 根据模块分配处理人
   - 设置预期完成时间
   - 通知相关人员

4. 问题处理
   - 分析问题原因
   - 制定解决方案
   - 实施修复
   - 更新问题状态

5. 问题验证
   - 验证修复效果
   - 回归测试
   - 确认问题解决

6. 问题关闭
   - 确认所有验证通过
   - 更新问题状态为已关闭
   - 归档问题记录
```

## 问题统计与报告

```
日常统计:
  - 新增问题数
  - 已解决问题数
  - 待处理问题数
  - 平均解决时间

周期报告:
  - 问题趋势图
  - 问题分布统计
  - 解决效率分析
  - 重复问题分析

质量指标:
  - 问题重开率 < 5%
  - 问题按时解决率 > 90%
  - 问题平均解决时间
  - 问题积压数量
```
