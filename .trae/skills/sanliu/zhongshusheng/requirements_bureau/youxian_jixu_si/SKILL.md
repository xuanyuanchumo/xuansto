# 优先级排序司

## 概述
优先级排序司负责建立科学的需求优先级评估体系，运用多种经过验证的优先级方法对需求 backlog 进行排序。本司综合考虑用户价值、业务目标、技术成本、风险因素等多维度指标，帮助团队在资源有限的情况下做出最优的需求排期决策，确保高价值需求优先交付。

## 核心职责
- MoSCoW 方法应用：将需求分类为 Must have / Should have / Could have / Won't have
- ICE 评分执行：基于 Impact（影响度）、Confidence（信心度）、Ease（简易度）三维打分
- WSJF 加权排序：运用加权最短作业优先方法，考虑业务价值、时间紧迫性、风险降低等因素
- ROI 评估：计算投入产出比，辅助商业决策
- Backlog 维护：持续维护与更新已排序的需求待办列表

## 输入与输出
| 输入 | 输出 |
|------|------|
| 需求列表（Backlog） | 优先级排序的需求 Backlog |
| 用户价值评估 | MoSCoW 分类结果 |
| 技术复杂度估算 | ICE 评分矩阵 |
| 时间约束与依赖 | WSJF 排序结果 |
| 成本预算信息 | ROI 分析报告 |

## 工作流程
1. **需求收集阶段**：汇聚来自各渠道的需求条目，形成初始 Backlog
2. **信息补充阶段**：收集每项需求的价值、成本、风险、依赖等元数据
3. **MoSCoW 初筛**：快速分类，识别 Must have 需求集合
4. **ICE 量化评估**：对 Should/Could 类需求进行三维打分
5. **WSJF 精细排序**：考虑时间敏感性与依赖关系，生成最终排序
6. **ROI 复核**：对高投入需求进行额外的投入产出比分析
7. **结果发布阶段**：输出排序后的 Backlog，同步给相关干系人

## 协作关系
- 上级局：需求分析局 (requirements_bureau)
- 协作司：用户研究司（用户价值输入）、需求拆解司（复杂度参考）
- 下游：尚书省-户部（资源分配）、兵部（迭代规划）
- 跨局协作：方案审议局-方案评审司（成本效益交叉验证）

## v4.0 新增能力
- 操作优先级：script（可使用脚本自动化 ICE/WSJF 计算与排序过程）
- 四维防线：
  - 第一防线：优先级方法论一致性（确保同一批次需求使用统一方法）
  - 第二防线：数据完整性校验（自动检测缺失的评估维度）
  - 第三防线：排序合理性审查（标记异常跳跃或倒挂的优先级）
- 资源协调：
  - 优先级评估工具（ProductBoard/Aha! 等集成）
  - 历史交付数据（用于校准估算模型）
  - 干系人偏好矩阵（决策者权重配置）
  - 决策日志系统集成（重大优先级变更需记录至 Decision Log）
