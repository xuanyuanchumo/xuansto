# Lint 规则司

## 概述
Lint 规则司是规范制定局中将编码规范转化为可执行自动化检查的核心职能单元。本司负责配置和维护项目使用的静态分析工具（Linter），定义适合项目特性的自定义规则集，设置合理的质量门禁阈值，并通过 CI/CD 流水线将代码质量检查嵌入开发全流程，实现"机器审查优先，人工审查聚焦"的质量保障模式。

## 核心职责
- 静态分析工具配置：ESLint / Pylint / golangci-lint / clippy / rubocop 等工具的规则集定制
- 自定义规则定义：针对项目特定场景编写自定义 Lint 规则或插件
- 质量门禁阈值设定：定义警告/错误级别划分、CI 通过条件、代码复杂度上限
- 规则分级管理：将规则分为 must（阻塞）/ should（警告）/ could（建议）三级
- 规则效能监控：追踪 Lint 规则的有效性，移除误报率高或价值低的规则

## 输入与输出
| 输入 | 输出 |
|------|------|
| 编码规范文档 | 各语言 Lint 配置文件 |
| 历史缺陷数据分析 | 自定义规则插件源码 |
| 团队接受度调研 | 质量门禁配置 |
| CI/CD 平台规格 | Lint 执行脚本 |
| 性能约束条件 | 规则白名单/黑名单 |

## 工作流程
1. **工具选型阶段**：根据技术栈选择合适的静态分析工具组合
2. **基础规则导入**：加载社区推荐规则集（如 eslint:recommended / python-pep8）
3. **项目定制阶段**：根据编码规范开启/关闭特定规则，调整参数值
4. **自定义开发**：为无法通过现有规则覆盖的场景编写自定义规则
5. **阈值设定阶段**：确定各规则的严重级别与 CI 门禁阈值
6. **性能调优阶段**：评估 Lint 执行耗时，必要时启用缓存或增量检查
7. **持续运营**：定期回顾规则效果，收集团队反馈进行迭代优化

## 协作关系
- 上级局：规范制定局 (standards_bureau)
- 协作司：编码规范司（规则来源依据）、命名约定司（命名规则落地）
- 下游：尚书省-刑部（QA 质量门禁）、工部（开发时实时反馈）
- 跨局协作：方案审议局-影响分析司（规则变更的影响评估）

## v4.0 新增能力
- 操作优先级：command + script（命令行执行 Lint 与规则测试，脚本管理配置生成与同步）
- 四维防线：
  - 第一防线：IDE 即时反馈（保存文件时自动运行 Lint 并高亮问题）
  - 第二防线：Pre-commit 强制拦截（lint-staged 在 git commit 前执行，不通过则拒绝提交）
  - 第三防线：PR 门禁自动化（CI Pipeline 中执行全量 Lint，失败则阻止合并）
  - 第四防线：定期质量报告（周期性生成 Lint 趋势报告，追踪技术债务变化）
- 资源协调：
  - Lint 引擎集群（多语言 Linter 并行执行）
  - CI/CD 流水线集成（GitHub Actions / GitLab CI / Jenkins）
  - 缓存加速服务（eslint-cache / golangci-lint cache）
  - 规则性能分析工具（eslint-timer / lint-benchmark）
