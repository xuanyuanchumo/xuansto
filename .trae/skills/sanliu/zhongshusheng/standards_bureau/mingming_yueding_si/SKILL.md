# 命名约定司

## 概述
命名约定司是规范制定局中专精于命名体系的职能单元，负责建立覆盖代码、数据、接口、基础设施等多层次的统一命名规范。良好的命名约定是代码可读性的基石，本司通过制定清晰、一致、自解释的命名规则，降低团队的认知负担与沟通成本，使代码库成为一份"自文档化"的知识资产。

## 核心职责
- 变量与函数命名：camelCase / snake_case / PascalCase 的场景化选用规则
- 类与模块命名：类名、接口名、抽象类的区分约定与后缀规范
- 文件与目录命名：文件名格式、目录层次组织的统一规则
- 数据库对象命名：表名、字段名、索引名、约束名的数据库命名规范
- API 端点命名：RESTful 资源路径、GraphQL 字段、gRPC Service 的接口命名规范
- 命名速查表维护：提供可快速查阅的命名规范参考卡片

## 输入与输出
| 输入 | 输出 |
|------|------|
| 技术栈信息 | 命名规范速查表 |
| 团队偏好调查 | 各层命名规则文档 |
| 语言官方惯例 | 命名冲突解决指南 |
| 现有代码库分析 | 违规命名修复建议 |
| 国际化需求 | 多语言命名策略 |

## 工作流程
1. **技术栈映射阶段**：针对项目中使用的每种语言/框架，确定其社区推荐的命名惯例
2. **分层规则定义**：按代码元素类型（变量/函数/类/文件/DB/API）分别制定规则
3. **特殊场景处理**：处理缩写、首字母词、专有名词、国际化等边界情况
4. **速查表编制**：将所有规则浓缩为一张便于开发者随时查阅的速查表
5. **工具规则同步**：将命名规则转化为 Lint 规则，实现自动化检测
6. **存量治理规划**：分析现有代码库的命名违规情况，制定渐进式修复计划
7. **持续迭代**：根据团队反馈与新引入的技术栈持续优化命名规范

## 协作关系
- 上级局：规范制定局 (standards_bureau)
- 协作司：编码规范司（整体规范一部分）、Lint 规则司（规则落地执行）
- 下游：尚书省-工部（开发执行）、刑部（Code Review 审查依据）
- 跨局协作：架构设计局-接口定义司（API 端点命名协同）

## v4.0 新增能力
- 操作优先级：script（可使用脚本自动化命名规范校验，批量重命名辅助生成）
- 四维防线：
  - 第一防线：IDE 实时提示（LSP 集成，编码时即时发现命名违规）
  - 第二防线：提交前自动检查（pre-commit hook 拦截不符合规范的命名）
  - 第三防线：CI 批量扫描（PR 时全量检测新增代码的命名合规性）
  - 第四防线：定期存量审计（周期性报告存量代码的命名健康度）
- 资源协调：
  - 命名 Lint 规则集（ESLint naming-convention / pylint naming 等）
  - IDE 代码片段模板（snippets 统一命名风格）
  - 重构工具支持（JetBrains Rename / gofmt / rustfix 等）
