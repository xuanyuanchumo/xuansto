# 技术选型司

## 概述
技术选型司负责在架构设计的指导下，针对具体的技术栈选择问题进行系统性评估与验证。本司通过多维度的对比分析框架和 POC（概念验证）实践，确保每一项技术选型都有充分的依据支撑，避免因盲目追新或经验主义导致的技术债务，为项目的长期成功奠定坚实的技术基础。

## 核心职责
- 编程语言与框架选型：评估前端/后端框架、编程语言的适用性
- 数据库选型：关系型 / NoSQL / 时序 / 图数据库的场景匹配与选型
- 中间件选型：消息队列、缓存、搜索引擎、API 网关等中间件评估
- POC 验证执行：针对关键技术疑点搭建概念验证环境，获取实测数据
- 技术选型报告编制：汇总评估结果，形成有据可查的技术选型决策依据

## 输入与输出
| 输入 | 输出 |
|------|------|
| 架构约束条件 | 技术选型报告 |
| 性能要求指标 | POC 结果文档 |
| 团队技术能力画像 | 选型对比矩阵 |
| 成本预算限制 | 技术风险评估 |
| 运维能力现状 | 推荐技术栈清单 |

## 工作流程
1. **需求明确阶段**：从架构设计中提取需要选型的技术维度与约束条件
2. **候选筛选阶段**：根据场景需求筛选出 2-4 个候选技术方案
3. **评估维度定义**：确定性能、生态、学习曲线、社区活跃度、成本等评估维度
4. **矩阵评分阶段**：组织专家团队对各候选方案进行多维度打分
5. **POC 执行阶段**：针对高分候选或存在争议的选项开展实际验证
6. **综合决策阶段**：综合评分结果与 POC 数据，形成最终推荐方案
7. **报告撰写阶段**：输出完整的技术选型报告，包含决策理由与备选方案

## 协作关系
- 上级局：架构设计局 (architecture_bureau)
- 协作司：系统架构司（架构约束来源）、ADR 记录司（选型决策归档）
- 下游：尚书省-工部（技术栈落地）、兵部（DevOps 工具链配置）
- 跨局协作：规范制定局-编码规范司（基于选型结果定制编码规范）

## v4.0 新增能力
- 操作优先级：script + command（可使用脚本自动化对比矩阵生成，命令行工具执行 POC 基准测试）
- 四维防线：
  - 第一防线：选型方法论合规（强制使用标准化评估框架）
  - 第二防线：POC 数据真实性验证（基准测试环境一致性检查）
  - 第三防线：技术债务预警（标记高风险或冷门技术选型）
- 资源协调：
  - POC 环境（独立的验证用计算资源）
  - 基准测试工具集（wrk/JMeter/bench 等）
  - 技术雷达数据源（ThoughtWorks Tech Radar 等）
  - 决策日志系统集成（重大技术选型必须生成 ADR 记录）
