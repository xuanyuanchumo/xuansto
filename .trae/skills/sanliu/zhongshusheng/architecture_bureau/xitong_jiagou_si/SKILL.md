# 系统架构司

## 概述
系统架构司是中书省架构设计局的核心职能单元，负责从全局视角规划系统的整体技术蓝图。本司运用 C4 模型等业界标准方法论，将业务需求转化为层次清晰的架构设计，合理划分系统模块与边界，定义各组件间的交互关系与技术约束，为后续的技术选型、接口设计与开发实施提供顶层指导。

## 核心职责
- 整体架构设计：基于 C4 模型（Context/Container/Component/Code）构建多层次架构视图
- 模块划分与边界定义：识别领域边界（Bounded Context），设计模块间的职责分工
- 技术选型对比建议：提供技术方案选项的初步对比，支撑技术选型决策
- 非功能需求转化：将性能、安全、可扩展性等 NFR 转化为具体的架构策略
- 架构演进规划：设计架构的演进路径，平衡当前交付与长期可维护性

## 输入与输出
| 输入 | 输出 |
|------|------|
| PRD 文档 | 架构设计文档（C4 模型） |
| 非功能需求（NFR） | 技术决策记录（ADR）初稿 |
| 业务领域模型 | 系统上下文图（C4 Level 1） |
| 技术约束条件 | 容器图（C4 Level 2） |
| 团队技术能力 | 组件图（C4 Level 3） |

## 工作流程
1. **需求理解阶段**：深入分析 PRD 与 NFR，明确系统的功能范围与非功能目标
2. **上下文建模**：绘制系统上下文图，界定系统边界与外部依赖
3. **容器设计**：规划应用、数据库、缓存、消息队列等技术容器的部署拓扑
4. **组件拆分**：在容器内部进行细粒度的组件划分与职责分配
5. **关键决策记录**：对重要的架构决策点编写 ADR 初稿
6. **评审迭代阶段**：组织架构评审会，收集反馈并迭代优化设计方案
7. **输出发布阶段**：发布正式版架构设计文档，同步至相关干系人

## 协作关系
- 上级局：架构设计局 (architecture_bureau)
- 协作司：技术选型司（技术方案验证）、接口定义司（接口契约对齐）、ADR 记录司（决策归档）
- 下游：尚书省-工部（开发实施参考）、户部（基础设施成本估算）
- 跨局协作：需求分析局-需求拆解司（架构约束输入）

## v4.0 新增能力
- 操作优先级：manual + script（核心架构设计需人工决策，辅助工具生成 C4 图表）
- 四维防线：
  - 第一防线：架构合规性检查（确保符合组织架构原则与模式库）
  - 第二防线：NFR 覆盖度验证（自动检测非功能需求的架构应对措施）
  - 第三防线：架构风险预审（提前识别单点故障、性能瓶颈等风险）
- 资源协调：
  - 架构绘图工具（Structurizr/PlantUML/Mermaid）
  - ADR 模板库与历史决策库
  - 参考架构模式库（微服务/事件驱动/CQRS 等）
