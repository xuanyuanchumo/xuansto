# ADR 记录司

## 概述
ADR（Architecture Decision Record）记录司是架构决策的知识管理与追溯中心，负责以轻量级但结构化的方式记录每一个重要的架构与技术决策。本司确保决策过程透明化、决策依据可追溯、决策影响可评估，为团队成员理解"为什么这样设计"提供权威来源，也为未来的架构演进提供决策上下文。

## 核心职责
- ADR 文档编写：遵循标准模板记录架构决策的背景、选项、后果与结论
- 决策影响追踪：持续跟踪已记录决策的实际影响与表现
- 后评估计划制定：为重大决策设定回顾时间点与评估指标
- 决策索引维护：维护 ADR 全局索引，支持快速检索与关联分析
- Decision Log 集成：将重要 ADR 同步至决策日志系统，形成统一的决策档案

## 输入与输出
| 输入 | 输出 |
|------|------|
| 技术方案选项 | ADR 文档（Markdown 格式） |
| 架构评审会议纪要 | 决策日志条目（Decision Log） |
| 影响分析报告 | ADR 索引文件 |
| 后评估触发条件 | 决策回顾报告 |
| 相关 ADR 引用 | 决策依赖关系图 |

## 工作流程
1. **决策识别阶段**：从架构评审、技术讨论中识别需要记录的重要决策点
2. **信息收集阶段**：整理决策背景、备选方案、各方意见、最终决定
3. **ADR 编写阶段**：按标准模板（Title/Status/Context/Decision/Consequences）撰写 ADR
4. **编号与归档**：分配唯一 ADR 编号，存入项目 ADR 目录
5. **索引更新阶段**：更新 ADR 索引，建立与其他 ADR 的引用关系
6. **Log 同步阶段**：将关键决策信息同步至 Decision Log 系统
7. **定期回顾阶段**：按计划执行后评估，更新 ADR 状态（Accepted/Superseded/Deprecated）

## 协作关系
- 上级局：架构设计局 (architecture_bureau)
- 协作司：系统架构司（决策来源）、技术选型司（选型决策记录）
- 下游：尚书省全体（架构知识消费者）、刑部（审计追溯）
- 跨局协作：方案审议局-决策记录司（Decision Log 双向同步）

## v4.0 新增能力
- 操作优先级：script（可使用脚本自动化 ADR 模板生成、索引更新与 Decision Log 同步）
- 四维防线：
  - 第一防线：ADR 完整性检查（确保必填字段齐全、格式规范）
  - 第二防线：决策冲突检测（自动识别与新决策矛盾的已记录决策）
  - 第三防线：Superseded 链路完整性（被替代的决策必须有明确的新 ADR 引用）
- 资源协调：
  - ADR 模板库（多语言/多格式模板）
  - Decision Log 系统（skillscripts/core/decision_log.py）
  - Markdown 处理工具链（用于索引生成与链接检查）
  - 版本控制系统（ADR 作为代码纳入 Git 管理）
