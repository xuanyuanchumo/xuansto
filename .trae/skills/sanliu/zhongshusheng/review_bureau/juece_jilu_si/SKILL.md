# 决策记录司 ⭐

## 概述
决策记录司是方案审议局的知识中枢与决策追溯中心，**集成 Decision Log 系统**，负责对项目全生命周期中的重要决策进行规范化记录与全链路管理。本司确保每一个关键决策都有完整的上下文留痕——包括决策背景、备选方案对比、影响范围分析、参与人员与决策理由——使团队能够在任意时间点回溯"为什么做出这个决策"，并为未来的架构演进与审计合规提供权威依据。

## 核心职责
- 重要决策记录：捕获项目中的架构决策、技术选型、方向调整等重要决策节点
- 决策依据追溯：记录支撑决策的数据、调研结果、专家意见等证据链
- 影响范围分析：评估决策对各模块、团队、用户群体的波及范围
- **Decision Log 系统集成**：
  - 调用 `skillscripts/core/decision_log.py`（Phase 5 创建的核心模块）
  - 自动生成 `DEC-YYYYMMDD-NNN` 格式的决策日志文件
  - 包含完整字段：决策ID、时间戳、决策者、决策类型、背景描述、备选方案评估矩阵、最终决策、影响范围、相关风险、后评估计划
- 决策日志维护：统一管理 `docs/logs/decision_logs/DEC-*.md` 格式的决策日志文件

## 输入与输出
| 输入 | 输出 |
|------|------|
| 决策上下文（会议纪要/讨论记录） | DEC-YYYYMMDD-NNN 决策日志文件 |
| 备选方案列表 | 决策索引（Decision Index） |
| 影响分析报告 | 决策依赖关系图 |
| 风险评估数据 | 决策统计仪表板数据 |
| 后评估触发条件 | 决策回顾报告 |

## 工作流程
1. **决策识别阶段**：从技术评审会、架构讨论、紧急变更中识别需要正式记录的决策
2. **信息收集阶段**：整理决策背景、备选方案、利弊分析、参会人员意见等完整上下文
3. **日志编写阶段**：调用 Decision Log 系统生成标准化决策日志：
   ```python
   # 调用 decision_log.py 创建决策记录
   python skillscripts/core/decision_log.py create \
     --title "决策标题" \
     --type "architecture|technology|process|emergency" \
     --decision-maker "决策者姓名/角色" \
     --context "背景描述" \
     --options "选项A:描述|选项B:描述" \
     --decision "最终选择及理由" \
     --impact "影响范围" \
     --risks "相关风险" \
     --review-plan "后评估计划"
   ```
4. **编号分配阶段**：系统自动分配 DEC-YYYYMMDD-NNN 格式的唯一决策ID
5. **文件归档阶段**：将生成的 Markdown 文件存入 `docs/logs/decision_logs/` 目录
6. **索引更新阶段**：更新全局 Decision Index，建立与其他决策/ADR 的引用关系
7. **后评估执行**：按计划周期回顾决策效果，更新决策状态（有效/需修正/已废弃）

## 协作关系
- 上级局：方案审议局 (review_bureau)
- 协作司：方案评审司（评审结论来源）、风险评估司（风险数据输入）、影响分析司（影响范围）
- 下流：尚书省全体（决策消费者）、刑部（审计追溯）
- 跨局协作：
  - 架构设计局-ADR 记录司（ADR 与 Decision Log 双向同步）
  - 需求分析局-优先级排序司（重大优先级变更需记录）

## v4.0 新增能力
- 操作优先级：command + script（**核心操作模式**：通过命令行调用 decision_log.py 执行全部决策记录操作）
- **Decision Log 系统集成详情**：
  ```
  集成路径: skillscripts/core/decision_log.py
  存储位置: docs/logs/decision_logs/
  文件命名: DEC-YYYYMMDD-NNN.md（如 DEC-20260101-001.md）
  支持命令:
    - create    : 创建新决策记录
    - list      : 列出所有决策记录
    - show      : 查看指定决策详情
    - update    : 更新已有决策（追加后评估结果）
    - search    : 按关键词/类型/时间范围搜索决策
    - export    : 导出决策汇总报告
    - link      : 建立/查看决策间的引用关系
  ```
- 四维防线：
  - 第一防线：决策完整性校验（必填字段缺失时拒绝创建）
  - 第二防线：决策冲突检测（新决策与已有决策矛盾时发出警告）
  - 第三防线：后评估到期提醒（到达预定回顾时间的决策自动通知负责人）
  - 第四防线：审计追踪完整性（所有决策操作均记录操作日志，不可篡改）
- 资源协调：
  - **Decision Log 核心**：skillscripts/core/decision_log.py（Phase 5 产物）
  - Markdown 处理引擎（用于日志文件的读写与校验）
  - Git 版本控制集成（决策日志纳入代码仓库管理）
  - 通知渠道（邮件/IM/项目管理工具，用于后评估提醒）
  - 搜索索引（支持全文检索决策内容）
