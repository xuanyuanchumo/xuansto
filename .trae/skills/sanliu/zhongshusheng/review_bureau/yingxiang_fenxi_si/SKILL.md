# 影响分析司

## 概述
影响分析司是方案审议局中专精于变更影响范围评估的职能单元。本司在面对需求变更、架构调整、技术升级等变动场景时，系统性分析其对现有系统各层面的波及程度，评估兼容性风险，规划平滑迁移路径，帮助团队在变革中保持可控，避免因低估影响范围导致的连锁故障或超预期的工作量膨胀。

## 核心职责
- 变更影响范围分析：识别变更对代码、数据、接口、配置、运维等各层的影响面
- 兼容性评估：评估变更对上游消费方、下游依赖方、并行系统的兼容性影响
- 迁移路径规划：设计从现状到目标状态的渐进式迁移方案，降低切换风险
- 回滚方案制定：为高风险变更设计快速回滚策略与回滚验证方法
- 影响分析报告编制：输出结构化的影响分析文档，供决策者与执行者参考

## 输入与输出
| 输入 | 输出 |
|------|------|
| 变更请求（CR） | 影响分析报告 |
| 架构设计文档 | 变更影响热力图 |
| 接口契约定义 | 兼容性矩阵 |
| 依赖关系图谱 | 迁移计划文档 |
| 部署拓扑图 | 回滚方案与检查清单 |

## 工作流程
1. **变更理解阶段**：深入理解变更的内容、动机、期望收益与非目标范围
2. **影响面初筛**：基于架构知识与依赖关系，初步圈定可能受影响的区域
3. **逐层深度分析**：
   - 代码层：受影响的模块、函数、数据结构
   - 数据层：Schema 变更、数据迁移需求、兼容性处理
   - 接口层：API 契约变化、版本兼容性、Mock 更新
   - 配置层：环境变量、配置文件、特性开关变更
   - 运维层：部署流程、监控告警、容量规划调整
4. **兼容性评估**：逐一评估每个影响点的向前/向后兼容性
5. **迁移路径设计**：规划分阶段迁移步骤，定义各阶段的验收条件
6. **回滚预案制定**：设计回滚触发条件、回滚步骤与回滚验证方法
7. **报告输出阶段**：整合所有分析成果，输出正式的影响分析报告

## 协作关系
- 上级局：方案审议局 (review_bureau)
- 协作司：方案评审司（变更方案评审输入）、风险评估司（变更风险联动）、决策记录司（重大变更决策归档）
- 下游：尚书省-工部（变更实施）、兵部（部署与回滚执行）
- 跨局协作：架构设计局-接口定义司（API 变更影响协同分析）、ADR 记录司（架构变更决策记录）

## v4.0 新增能力
- 操作优先级：script + command（脚本自动化依赖图分析与影响面扫描，命令行工具执行兼容性检测）
- 四维防线：
  - 第一防线：影响面完整性检查（自动检测是否遗漏关键的依赖模块）
  - 第二防线：Breaking Change 识别（自动标记可能破坏兼容性的变更点）
  - 第三防线：回滚可行性验证（回滚方案必须在预发环境通过演练）
  - 第四防线：影响过度预警（当影响范围超过阈值时触发人工复核）
- 资源协调：
  - 依赖分析工具（dependency-cruiser / madge / dep 等）
  - API 兼容性检测工具（openapi-diff / backstopjs 等）
  - 代码搜索与影响分析引擎（grep/ast-grep/CodeQuery）
  - 决策日志系统集成（高影响变更的决策需记录至 Decision Log）
  - 变更管理系统（Jira/Linear 变更工作流集成）
