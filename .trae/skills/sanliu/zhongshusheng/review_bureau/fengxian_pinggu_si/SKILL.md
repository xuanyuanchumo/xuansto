# 风险评估司

## 概述
风险评估司是方案审议局中专精于技术风险识别与量化的职能单元。本司运用系统化的风险管理方法论，主动识别架构设计与技术方案中的潜在风险点，对风险进行概率与影响的量化评估，制定针对性的缓解策略与应急预案，为项目决策提供风险维度的专业支撑，降低项目失败概率。

## 核心职责
- 技术风险识别：从架构、性能、安全、兼容性、供应链等多维度识别潜在风险
- 风险量化评估：采用概率×影响矩阵对识别出的风险进行分级排序
- 缓解策略制定：针对高优先级风险制定规避、转移、减轻、接受等应对措施
- 风险登记册维护：维护项目级 Risk Register，持续更新风险状态
- 风险预警机制：设定风险触发指标（Trigger），实现风险的早期预警

## 输入与输出
| 输入 | 输出 |
|------|------|
| 架构设计方案 | 风险登记册（Risk Register） |
| 技术选型报告 | 风险热力图 |
| 历史项目故障数据 | 缓解策略矩阵 |
| 外部依赖清单 | 应急预案文档 |
| 团队能力画像 | 风险趋势报告 |

## 工作流程
1. **风险场景枚举**：基于设计方案，系统性地枚举可能的风险场景（使用风险分解结构 RBS）
2. **风险筛选过滤**：去除重复项与极低概率项，形成初始风险列表
3. **量化评估打分**：对每项风险的发生概率和影响程度进行评分（1-5 分制）
4. **矩阵定位分级**：将风险标注在概率-影响矩阵上，确定风险等级（高/中/低）
5. **缓解策略设计**：针对高/中风险制定具体的缓解行动与责任人
6. **登记册编制**：将所有风险信息整理为标准格式的 Risk Register
7. **持续监控更新**：定期回顾风险状态，更新概率/影响评估与应对措施

## 协作关系
- 上级局：方案审议局 (review_bureau)
- 协作司：方案评审司（提供风险维度评审输入）、影响分析司（变更风险联动）
- 下游：尚书省-兵部（迭代风险管控）、刑部（安全审计）
- 跨局协作：需求分析局-用户研究司（用户侧风险洞察）

## v4.0 新增能力
- 操作优先级：script + command（脚本自动化风险矩阵计算与热力图生成，命令行工具扫描依赖风险）
- 四维防线：
  - 第一防线：风险覆盖率检查（确保关键架构组件均有对应风险条目）
  - 第二防线：高风險门禁（存在未缓解的高风险时阻断发布流程）
  - 第三防线：风险过期提醒（长时间未更新的风险条目自动标记）
- 资源协调：
  - 风险管理工具（Risk Register 模板/平台）
  - 依赖扫描工具（Dependabot/Snyk/OSS Index）
  - 安全漏洞数据库（CVE/NVD 集成）
  - 决策日志系统集成（高风险决策需记录至 Decision Log 并附带风险说明）
