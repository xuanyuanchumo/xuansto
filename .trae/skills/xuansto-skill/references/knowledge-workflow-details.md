# 知识工作流详细文档

## 知识服务生命周期

知识服务存在三种状态：

### 可用态
- 通过 MCP Tool 或 REST API 提供完整知识服务
- 支持语义检索、上下文注入、经验沉淀全流程
- 响应延迟低，检索精度高

### 不可用态
- MCP 服务和 REST API 均不可用时降级为文件系统模式
- 仅支持关键词匹配检索
- 检索精度降低，但仍可提供基础知识支撑

### 降级态
- 当 Token 使用率 ≥ 80% 时自动降级
- 检索策略降级为 keyword-only 模式
- 仅返回最相关的核心条目，减少上下文注入量
- 优先保障当前任务完成，暂停经验沉淀

## 三阶段知识工作流

### 第一阶段：Retrieve（检索）

完整流程：

1. **解析任务类型** - 识别当前任务属于 bug_fix / feature / review / deploy / security / coding_standard / error_handling / tech_selection 中的哪一类
2. **检测技术栈** - 扫描项目文件识别语言、框架、工具链
3. **选择检索策略** - 根据任务类型和技术栈选择最优检索路径
4. **渐进式检索** - 按优先级依次检索：项目本地知识 → 全局经验库 → 外部知识源
5. **Token 预算控制** - 单次检索 Token 预算上限 2048，超出时截取最相关片段

检索策略映射：

| 任务类型 | 优先检索源 | 检索深度 |
|---------|-----------|---------|
| bug_fix | 错误模式库 > 经验库 | 深度 |
| feature | 模式库 > 最佳实践 | 中等 |
| review | 编码规范 > 安全规则 | 浅层 |
| deploy | 部署经验 > 环境配置 | 中等 |
| security | 安全规则 > 漏洞库 | 深度 |

### 第二阶段：Inject（注入）

将检索到的知识注入当前上下文：

1. **格式化** - 统一为结构化格式，包含标题、内容、来源、置信度
2. **标注来源和置信度** - 每条知识标注数据源和可信度评分
3. **按相关性排序** - 根据任务匹配度降序排列
4. **超长截取 summary** - 当注入内容超过 Token 预算时，截取摘要并标注 `[TRUNCATED]`

注入格式示例：

```
[KNOWLEDGE-INJECT]
来源: {source}
置信度: {confidence}
相关性: {relevance_score}
---
{content}
[/KNOWLEDGE-INJECT]
```

### 第三阶段：Precipitate（沉淀）

任务完成后将经验沉淀到知识库：

1. **提取关键信息** - 从任务执行过程中提取有价值的知识点
2. **生成经验条目** - 结构化为标准经验条目格式
3. **写入去重** - 与已有条目比对，避免重复沉淀
4. **初始置信度** - 根据条目类型赋予初始置信度：
   - bug_fix: 0.70
   - pattern: 0.75
   - optimization: 0.70
5. **3-Strike 失败沉淀** - 同一问题连续失败 3 次时强制沉淀，置信度设为 0.40

经验条目结构：

```json
{
  "id": "auto-generated",
  "type": "bug_fix | pattern | optimization",
  "title": "简明描述",
  "content": "详细内容",
  "tech_stack": ["语言", "框架"],
  "confidence": 0.70,
  "source": "precipitate",
  "created_at": "ISO8601",
  "hit_count": 0,
  "success_count": 0
}
```

## 知识库自动触发场景

以下场景自动触发知识工作流：

| 场景 | 触发条件 | 优先级 |
|------|---------|--------|
| Bug修复 | 检测到错误修复任务 | 高 |
| 功能实现 | 检测到新功能开发任务 | 高 |
| 代码审查 | 检测到代码审查请求 | 中 |
| 部署上线 | 检测到部署相关操作 | 高 |
| 安全审计 | 检测到安全相关任务 | 高 |
| 编码规范查询 | 检测到规范相关提问 | 中 |
| 错误处理 | 检测到异常处理逻辑 | 中 |
| 技术选型 | 检测到技术方案选择 | 中 |

触发机制：
- 基于任务关键词自动识别
- 基于上下文语义分析
- 基于用户显式请求

## Trae/Claude Code 集成调用

知识服务集成遵循三级降级策略：

### 第一优先级：MCP Tool
- 通过 MCP 协议直接调用知识服务工具
- 支持语义检索、精确查询、经验沉淀
- 延迟最低，功能最完整
- 调用方式：`knowledge_search` / `knowledge_inject` / `knowledge_precipitate`

### 第二优先级：REST API
- MCP 不可用时通过 HTTP 接口调用
- 支持核心检索和沉淀功能
- 需要配置 API 端点和认证信息
- 端点：`/api/knowledge/search` / `/api/knowledge/precipitate`

### 第三优先级：文件系统兜底
- 所有远程服务不可用时使用本地文件系统
- 读取 `.knowledge/` 目录下的结构化文件
- 仅支持关键词匹配检索
- 沉淀操作直接写入本地文件

降级判断流程：

```
尝试 MCP Tool 调用
  ↓ 失败/超时(>5s)
尝试 REST API 调用
  ↓ 失败/超时(>10s)
降级为文件系统模式
```

## 持续学习闭环

持续学习闭环实现知识从临时经验到正式条目的演化：

### 模式提取
- 监控任务执行记录，识别重复模式
- 触发条件：相同错误出现 ≥ 2 次
- 自动提取共性特征，生成模式草稿

### 技能草稿生成
- 草稿存放路径：`.knowledge/experience/patterns/`
- 包含模式描述、触发条件、解决方案
- 状态标记为 `draft`，不参与正式检索

### 验证
- 后续任务中若成功应用该草稿模式
- 验证通过后提升 confidence
- 每次成功应用：`confidence = min(confidence + 0.05, 1.0)`

### 沉淀
- 当 confidence ≥ 0.8 时，草稿升级为正式条目
- 移入正式知识库，参与常规检索
- 标记状态为 `active`，开始积累 hit_count 和 success_count

闭环流程：

```
模式提取(相同错误≥2次)
  → 技能草稿生成(.knowledge/experience/patterns/)
    → 验证(后续成功应用→confidence升级)
      → 沉淀(≥0.8正式条目)
```

置信度演化路径：

```
bug_fix:     0.40(3-Strike) → 0.70(初始) → ... → 0.80(正式) → 1.0(上限)
pattern:     0.40(3-Strike) → 0.75(初始) → ... → 0.80(正式) → 1.0(上限)
optimization: 0.40(3-Strike) → 0.70(初始) → ... → 0.80(正式) → 1.0(上限)
```
