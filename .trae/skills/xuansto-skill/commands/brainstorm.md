# /brainstorm 命令

## 命令描述

启动6阶段苏格拉底式需求探索流程，引导用户从模糊想法逐步探索到结构化设计文档。该命令通过逐个提问、方案对比、设计反思等结构化对话，确保需求完整、方案合理、设计可实施。

## 触发条件

| 触发方式 | 说明 |
|----------|------|
| 命令输入 | 用户输入 `/brainstorm` |
| 关键词触发 | 用户提及"需求探索"、"头脑风暴"、"brainstorm"、"苏格拉底" |
| 自动触发 | 检测到用户描述模糊需求时自动建议 |
| 条件触发 | 需求描述过于简略或缺乏细节时 |

## 命令名称与语法

```
/brainstorm <topic> [--depth=<深度>] [--output=<输出路径>]
```

## 参数定义

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `<topic>` | string | 是 | - | 探索主题或模糊需求描述 |
| `--depth` | enum | 否 | standard | 探索深度：quick/standard/thorough |
| `--output` | path | 否 | .agent_cache/<task>/ | 设计文档输出路径 |
| `--skip-reflect` | flag | 否 | false | 跳过Phase 4设计反思（不推荐） |
| `--auto-commit` | flag | 否 | true | 自动提交设计文档到设计分支 |

### 步骤详情

1. **Phase 1: Discovery（需求发现）**
   - 接收探索主题，扫描代码库了解现有架构
   - 识别与主题相关的信息缺口
   - 按优先级排序，每次只问1个问题
   - 记录所有回答和假设

2. **Phase 2: Option Analysis（方案分析）**
   - 基于Phase 1回答，生成2-4个可行方案
   - 进行Trade-off对比分析
   - 呈现对比矩阵，等待用户选择

3. **Phase 3: Design Creation（设计创建）**
   - 基于选定方案生成结构化设计文档
   - 包含目标、范围、架构、数据模型、接口、约束、风险
   - 用户确认设计文档

4. **Phase 4: Design Reflection（设计反思）**
   - 反向挑战设计，提出3-5个挑战性问题
   - 识别遗漏的场景、边界条件、异常处理
   - 修正设计文档，用户确认修正

5. **Phase 5: Git Commit（设计提交）**
   - 保存设计文档到 `.agent_cache/<task>/design-document.md`
   - 创建设计分支 `design/<task-name>`
   - 提交设计文档

6. **Phase 6: Transition（交接过渡）**
   - 生成交接摘要
   - 标注关键决策点和约束
   - 建议下一步操作

## 质量门禁

| 门禁标识 | 阶段 | 阻塞级别(BLOCK/WARN) | 通过标准 |
|----------|------|----------------------|----------|
| BRAINSTORM-COMPLETE | Phase 1 | BLOCK | 设计文档已生成+用户确认+6阶段全部完成 |

brainstorm完成后自动执行：

- [ ] 设计文档已生成
- [ ] 用户已确认设计
- [ ] 6阶段全部完成
- [ ] 设计文档已提交到设计分支
- [ ] 交接摘要已生成

## 示例用法

### 示例1：标准探索

```
/brainstorm 实现用户认证系统
```

### 示例2：深度探索

```
/brainstorm 设计一个实时协作编辑器 --depth=thorough
```

### 示例3：指定输出路径

```
/brainstorm 添加支付功能 --output=./docs/designs/
```

### 示例4：快速探索

```
/brainstorm 优化首页加载速度 --depth=quick
```
