# GoF 设计模式索引

GoF (Gang of Four) 23 种经典设计模式，分为三大类。

## 创建型模式 (Creational)

控制对象创建方式，隐藏创建逻辑，使系统独立于对象的创建/组合/表示。

| 模式 | 简述 |
|------|------|
| **Abstract Factory** | 提供创建一系列相关对象的接口，无需指定具体类 |
| **Builder** | 将复杂对象的构建与表示分离，支持分步构建 |
| **Factory Method** | 定义创建对象的接口，由子类决定实例化哪个类 |
| **Prototype** | 通过克隆原型实例创建新对象，避免重新初始化 |
| **Singleton** | 确保类只有一个实例，提供全局访问点 |

## 结构型模式 (Structural)

处理类和对象的组合方式，定义对象间的关系以形成更大结构。

| 模式 | 简述 |
|------|------|
| **Adapter** | 将一个类的接口转换为客户端期望的接口，解决兼容性问题 |
| **Bridge** | 将抽象与实现分离，使两者可独立变化 |
| **Composite** | 将对象组合成树形结构，统一对待单个对象和组合对象 |
| **Decorator** | 动态给对象添加职责，比继承更灵活的扩展方式 |
| **Facade** | 为子系统提供统一的高层接口，简化使用复杂度 |
| **Flyweight** | 共享细粒度对象，减少内存占用 |
| **Proxy** | 为对象提供代理以控制访问，支持延迟加载和访问控制 |

## 行为型模式 (Behavioral)

描述对象间的通信和职责分配，定义对象间的协作方式。

| 模式 | 简述 |
|------|------|
| **Chain of Responsibility** | 将请求沿处理链传递，直到有对象处理它 |
| **Command** | 将请求封装为对象，支持撤销/排队/日志 |
| **Interpreter** | 定义语言的文法表示，提供解释器 |
| **Iterator** | 顺序访问集合元素，不暴露集合内部结构 |
| **Mediator** | 用中介对象封装对象间交互，降低直接耦合 |
| **Memento** | 捕获对象内部状态，支持后续恢复（撤销机制） |
| **Observer** | 定义对象间一对多依赖，状态变化自动通知 |
| **State** | 允许对象在状态变化时改变行为，类层次替代条件分支 |
| **Strategy** | 定义算法族并封装，使算法可独立于客户端变化 |
| **Template Method** | 定义算法骨架，子类实现具体步骤 |
| **Visitor** | 在不改变类的前提下定义新操作，分离数据结构与操作 |
