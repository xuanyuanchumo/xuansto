# Token降级策略详细文档

## 三级渐进降级策略

### L1 - 轻度降级（Token使用率≥80%）

| 维度 | 降级措施 |
|------|----------|
| 并行Agent | 减少并行Agent数量，`max_parallel_agents=5` |
| MCP工具 | 禁用非关键MCP工具 |
| 模型路由 | 快速模型优先（搜索/简单编辑用Haiku级） |
| 搜索策略 | 从`hybrid`降级为`keyword-only` |
| 知识条目 | Top-5→Top-2 |

### L2 - 中度降级（Token使用率≥95%）

| 维度 | 降级措施 |
|------|----------|
| 运行模式 | 精简模式，仅保留核心层：orchestration / engineering / testing / security |
| Agent数量 | `max_agents=15` |
| MCP工具 | 仅启用核心MCP |
| 模型路由 | 标准模型（编码用Sonnet级） |

### L3 - 重度降级（Token使用率=100%）

| 维度 | 降级措施 |
|------|----------|
| 运行模式 | 最小串行模式 |
| Agent数量 | `min_agents=3` |
| MCP工具 | 无MCP，全部禁用 |
| 模型路由 | 深度模型（仅核心推理用Opus级） |

## 恢复策略

- Token比例降至0.6以下时逐步恢复
- `stepwise: true`（逐步恢复而非一次性恢复）
- 恢复顺序：L3→L2→L1→正常，每级恢复后观察Token使用情况再决定是否继续恢复

## MCP降级规则

### MCP工具上下文占用

- 每个MCP工具占用上下文窗口约5-10%
- 同时启用的MCP工具不超过10个

### 降级触发条件

| Token使用率 | MCP策略 |
|-------------|---------|
| <80% | 全部MCP可用（受10个上限约束） |
| ≥80% | 禁用非关键MCP |
| ≥95% | 仅核心MCP |
| =100% | 无MCP |

### CLI替代方案

| MCP工具 | CLI替代 |
|---------|---------|
| GitHub | `gh` CLI |
| Supabase | `supabase` CLI |
| Vercel | `vercel` CLI |

## 模型路由降级

| 降级级别 | 模型选择 | 适用场景 |
|----------|----------|----------|
| L1 | 快速模型优先（Haiku级） | 搜索、简单编辑、格式化 |
| L2 | 标准模型（Sonnet级） | 编码、重构、调试 |
| L3 | 深度模型（Opus级） | 仅核心推理、架构决策、安全审计 |

### 模型路由决策逻辑

- L1阶段：优先使用快速模型完成非核心任务，节省Token用于关键操作
- L2阶段：使用标准模型平衡速度与质量，确保编码任务的基本质量
- L3阶段：仅对核心推理任务使用深度模型，其余任务暂缓或串行等待

## Per-Phase Token预算

| 阶段 | Token预算 |
|------|-----------|
| phase_0 | 10000 |
| phase_1 | 15000 |
| phase_2 | 20000 |
| phase_3 | 10000 |
| phase_4 | 30000 |
| phase_5 | 15000 |
| phase_6 | 8000 |
| phase_7 | 12000 |
| phase_8 | 10000 |
| per_agent_default | 20000 |

### 预算分配原则

- phase_4（实现阶段）分配最高预算30000，因为代码生成是Token消耗最大的环节
- phase_6（收尾阶段）分配最低预算8000，仅执行必要的清理和验证
- 每个Agent默认预算20000，确保单个Agent不会过度消耗全局Token池
- 当单阶段Token预算耗尽时，触发该阶段内的微降级（减少输出长度、跳过非关键步骤）
