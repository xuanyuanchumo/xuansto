# /rollback 命令

## 命令描述

`/rollback` 命令用于部署回滚与版本恢复，是生产环境故障恢复的关键命令。该命令管理从版本验证到回滚执行的完整恢复流程，支持指定版本回滚、环境切换与模拟回滚，确保回滚过程安全、可控、可验证，最大限度减少故障影响时间。

---

## 触发条件

| 触发方式 | 说明 |
|----------|------|
| 命令输入 | 用户输入 `/rollback` |
| 关键词触发 | 用户提及"回滚"、"版本恢复"、"revert"、"回退" |
| 自动触发 | 部署后健康检查失败时自动建议回滚 |
| 流程触发 | 监控告警触发自动回滚策略 |

---

## 命令名称与语法

```
/rollback [options]
```

---

## 参数定义

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| --to | string | 否 | previous | 目标版本号或标签 |
| --env | string | 否 | production | 目标环境：staging、production |
| --dry-run | boolean | 否 | false | 模拟回滚，不执行实际变更 |
| --skip-backup | boolean | 否 | false | 跳过回滚前备份 |
| --skip-data-restore | boolean | 否 | false | 跳过数据恢复 |
| --force | boolean | 否 | false | 强制回滚，跳过安全检查 |
| --timeout | number | 否 | 300 | 回滚超时时间（秒） |
| --notify | string | 否 | all | 通知对象：all、team、stakeholders、none |
| --auto-verify | boolean | 否 | true | 回滚后自动验证 |

## 示例用法

### 示例1: 标准回滚

```bash
/rollback
```

回滚到上一个版本，默认生产环境。

### 示例2: 指定版本回滚

```bash
/rollback --to v1.2.0 --env production
```

回滚生产环境到v1.2.0版本。

### 示例3: 模拟回滚

```bash
/rollback --dry-run
```

模拟回滚过程，不执行实际变更。

### 示例4: Staging环境回滚

```bash
/rollback --env staging --to v1.1.0
```

回滚staging环境到v1.1.0版本。

### 示例5: 强制回滚

```bash
/rollback --to v1.2.0 --force
```

强制回滚到v1.2.0，跳过安全检查（仅限紧急情况）。

---

## 注意事项

1. **版本验证**: 回滚前务必验证目标版本的完整性与可用性
2. **数据兼容**: 数据库回滚需确认Schema兼容性，避免数据丢失
3. **备份优先**: 回滚前创建当前状态备份，确保可恢复
4. **安全审查**: 回滚到旧版本可能引入已修复的安全漏洞
5. **通知机制**: 生产环境回滚必须通知相关干系人
