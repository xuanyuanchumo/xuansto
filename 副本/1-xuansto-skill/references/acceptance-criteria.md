# 验收标准参考文档

## 验收标准编写

### 验收标准概述

验收标准（Acceptance Criteria，AC）是定义用户故事完成条件的具体标准，用于确保开发团队和利益相关者对功能期望达成一致。

### 验收标准格式

#### Given-When-Then格式 (Gherkin)

```gherkin
Feature: 用户登录功能

Scenario: 使用正确的凭据登录
  Given 用户在登录页面
  And 用户已注册账号 "user@example.com"
  When 用户输入邮箱 "user@example.com"
  And 用户输入密码 "correctPassword"
  And 用户点击登录按钮
  Then 用户应该被重定向到首页
  And 用户应该看到欢迎消息

Scenario: 使用错误的密码登录
  Given 用户在登录页面
  And 用户已注册账号 "user@example.com"
  When 用户输入邮箱 "user@example.com"
  And 用户输入密码 "wrongPassword"
  And 用户点击登录按钮
  Then 用户应该看到错误消息 "邮箱或密码错误"
  And 用户应该仍在登录页面

Scenario: 登录失败次数限制
  Given 用户在登录页面
  And 用户已连续登录失败4次
  When 用户再次使用错误密码登录
  Then 用户应该看到错误消息 "登录失败次数过多，请15分钟后再试"
  And 登录按钮应该被禁用
```

#### 检查清单格式

```markdown
## 用户故事：用户登录

### 验收标准：
- [ ] 支持邮箱+密码登录
- [ ] 支持手机号+密码登录
- [ ] 支持记住登录状态（7天）
- [ ] 登录失败显示错误提示
- [ ] 连续失败5次后锁定15分钟
- [ ] 登录成功后跳转到来源页面或首页
- [ ] 密码输入框支持显示/隐藏切换
- [ ] 表单验证：邮箱格式、密码非空
- [ ] 支持键盘Enter提交
- [ ] 移动端响应式布局正确
```

#### 表格格式

| 场景 | 输入 | 预期结果 | 边界条件 |
|------|------|----------|----------|
| 正常登录 | 有效邮箱+密码 | 登录成功，跳转首页 | - |
| 密码错误 | 有效邮箱+错误密码 | 显示错误提示 | - |
| 账号不存在 | 未注册邮箱 | 显示错误提示 | - |
| 空邮箱 | 空+密码 | 显示"请输入邮箱" | - |
| 空密码 | 邮箱+空 | 显示"请输入密码" | - |
| 格式错误 | 无效邮箱格式 | 显示"邮箱格式不正确" | - |

### 验收标准编写原则

#### INVEST原则

| 原则 | 说明 | 示例 |
|------|------|------|
| Independent | 独立的，不依赖其他故事 | 登录功能独立于注册功能 |
| Negotiable | 可协商的，细节可讨论 | 登录方式可以协商调整 |
| Valuable | 有价值的，对用户有价值 | 登录让用户访问个人数据 |
| Estimable | 可估算的，能评估工作量 | 登录功能约3人天 |
| Small | 足够小的，一个迭代可完成 | 不包含OAuth等扩展功能 |
| Testable | 可测试的，有明确验收标准 | 可以验证登录成功/失败 |

#### SMART原则

| 原则 | 说明 | 示例 |
|------|------|------|
| Specific | 具体的 | "登录响应时间<500ms"而非"快速响应" |
| Measurable | 可衡量的 | "测试覆盖率≥80%" |
| Achievable | 可实现的 | 基于团队能力和资源 |
| Relevant | 相关的 | 与用户故事直接相关 |
| Time-bound | 有时限的 | "在Sprint 5完成" |

### 验收标准示例

#### 功能性验收标准

```markdown
## 功能：购物车

### 用户故事
作为购物者，我希望能够管理购物车中的商品，以便在结账前调整购买内容。

### 验收标准

#### 添加商品
- [ ] 点击"加入购物车"后，商品添加到购物车
- [ ] 购物车图标显示商品数量角标
- [ ] 相同商品数量累加，不重复添加
- [ ] 显示添加成功提示（3秒后消失）
- [ ] 库存不足时显示"库存不足"提示

#### 修改数量
- [ ] 支持数量输入框直接输入
- [ ] 支持加减按钮调整数量
- [ ] 数量最小值为1
- [ ] 数量最大值为库存数量
- [ ] 修改数量后自动更新小计和总计

#### 删除商品
- [ ] 点击删除按钮弹出确认对话框
- [ ] 确认后移除商品
- [ ] 购物车为空时显示"购物车是空的"
- [ ] 支持撤销删除操作（5秒内）

#### 价格计算
- [ ] 显示商品单价
- [ ] 显示商品小计（单价×数量）
- [ ] 显示购物车总计
- [ ] 显示优惠金额（如有）
- [ ] 显示运费（根据规则计算）
```

## DoD定义

### Definition of Done (DoD)

DoD是团队对"完成"的统一定义，确保每个增量都达到可发布状态。

### DoD层级结构

### DoD vs DoR

| 维度 | DoD (Definition of Done) | DoR (Definition of Ready) |
|------|--------------------------|---------------------------|
| 定义 | 工作完成的定义 | 工作准备开始的定义 |
| 时机 | Sprint结束时 | Sprint开始前 |
| 目的 | 确保质量一致 | 确保可执行性 |
| 检查对象 | 已完成的工作 | 待开始的工作 |

### 验收角色职责

| 角色 | 职责 | 验收活动 |
|------|------|----------|
| 开发人员 | 实现功能、自测 | 代码提交、单元测试 |
| 测试人员 | 功能测试、回归测试 | 测试用例执行、缺陷报告 |
| Product Owner | 业务验收 | UAT验收、优先级确认 |
| 技术负责人 | 技术验收 | Code Review、架构评审 |
| 用户代表 | 最终验收 | UAT测试、反馈收集 |

### 验收环境

```yaml
验收环境配置:
  开发环境:
    用途: 开发自测
    数据: 模拟数据
    访问: 开发团队
    更新频率: 持续部署

  测试环境:
    用途: QA测试
    数据: 测试数据
    访问: 测试团队
    更新频率: 每日构建

  UAT环境:
    用途: 用户验收测试
    数据: 类生产数据
    访问: PO、用户代表
    更新频率: 按需部署

  预发布环境:
    用途: 发布前验证
    数据: 生产数据副本
    访问: 限定人员
    更新频率: 发布前部署
```
