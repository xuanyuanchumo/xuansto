# 会话持久化机制

## 概述

会话持久化机制通过 Stop Hook 和 SessionStart Hook 实现跨会话上下文保存与恢复，遵循 ECC 的会话存储模式。该机制确保 Agent 在会话切换时不会丢失关键上下文，实现工作流的连续性与一致性。

核心目标：

- 会话结束时自动保存关键状态与决策信息
- 新会话启动时自动恢复上下文，避免从零开始
- 上下文压缩前持久化关键数据，防止信息丢失

---

## Stop Hook 行为

会话结束时，Stop Hook 自动生成会话摘要文件，将当前会话的关键信息持久化到磁盘。

### 文件路径

```
.skill-logs/session-{timestamp}.md
```

其中 `{timestamp}` 格式为 `YYYYMMDD-HHmmss`，例如 `session-20250512-143025.md`。

### 摘要结构

摘要包含四个必填段落：

| 段落 | 用途 | 必填 |
|------|------|------|
| 已完成任务清单 | 记录本会话中完成的所有任务，附验证证据 | 是 |
| 未完成任务清单 | 记录本会话中未完成的任务及原因 | 是 |
| 关键决策记录 | 记录本会话中做出的重要决策及理由 | 是 |
| 经验沉淀条目 | 记录本会话中积累的经验，附置信度评分 | 是 |

### 触发时机

- 用户主动结束会话
- 会话超时
- Agent 进程正常退出
- 任何导致会话终止的事件

## SessionStart Hook 行为

新会话启动时，SessionStart Hook 自动加载最近的会话摘要，为当前会话提供上下文延续。

### 加载策略

仅加载最近一个会话摘要，避免上下文污染。加载过多历史摘要会导致上下文窗口被占用，降低当前会话的有效推理空间。

### 提供的上下文延续信息

SessionStart Hook 加载摘要后，向当前会话提供以下三类关键信息：

1. **什么方法有效（附证据）**：上一会话中验证通过的策略与方法，附带具体的验证证据，帮助当前会话直接复用已验证的方案。
2. **什么方法无效**：上一会话中尝试失败的方法与路径，帮助当前会话避免重复踩坑。
3. **还有什么未尝试**：上一会话中识别但尚未探索的方向，帮助当前会话快速定位下一步行动。

### 加载流程

1. 扫描 `.skill-logs/` 目录下的所有 `session-*.md` 文件
2. 按时间戳降序排序
3. 读取最近一个摘要文件
4. 解析四个必填段落
5. 将上下文延续信息注入当前会话

---

## 会话摘要格式

```markdown
# Session {timestamp}

## 已完成任务
- [任务描述] — 验证: [证据]

## 未完成任务
- [任务描述] — 原因: [说明]

## 关键决策
- [决策描述] — 理由: [说明]

## 经验沉淀
- [经验描述] — confidence: [0.0-1.0]
```

### 格式说明

- **已完成任务**：每个条目包含任务描述和验证证据。验证证据应为可观测的结果，例如测试通过、构建成功、输出截图等。
- **未完成任务**：每个条目包含任务描述和未完成原因。原因应具体说明阻塞因素或依赖关系。
- **关键决策**：每个条目包含决策描述和决策理由。理由应说明为什么选择该方案而非其他备选方案。
- **经验沉淀**：每个条目包含经验描述和置信度评分。置信度范围为 0.0 到 1.0，其中 1.0 表示高度确信，0.0 表示仅为推测。

### 示例

```markdown
# Session 20250512-143025

## 已完成任务
- 实现用户认证模块 — 验证: 全部 12 个单元测试通过
- 修复登录页面样式错位 — 验证: 截图对比确认布局正确

## 未完成任务
- 集成第三方支付接口 — 原因: 等待支付平台沙箱环境开通
- 性能压力测试 — 原因: 依赖支付接口集成完成

## 关键决策
- 选择 JWT 而非 Session 进行身份认证 — 理由: 项目为分布式架构，JWT 无需服务端状态存储
- 使用 Redis 缓存热点数据 — 理由: 压测显示数据库查询为瓶颈，缓存可降低 80% 读取延迟

## 经验沉淀
- React 表单状态管理优先使用受控组件 — confidence: 0.9
- WebSocket 重连策略应采用指数退避 — confidence: 0.85
- 大型列表渲染必须使用虚拟滚动 — confidence: 0.95
```

## PreCompact Hook 行为

上下文压缩（Compact）前，PreCompact Hook 保存关键状态到 `.agent_cache/` 目录，防止压缩过程中丢失不可恢复的信息。

### 持久化内容

| 内容 | 文件路径 | 说明 |
|------|----------|------|
| Decision Log | `.agent_cache/decision-log.json` | 当前会话的所有决策记录 |
| 当前 Phase | `.agent_cache/current-phase.json` | 当前所处的工作流阶段 |
| 工作流状态 | `.agent_cache/workflow-state.json` | 工作流的完整状态快照 |

### 触发时机

- 上下文窗口使用率超过阈值，系统触发自动压缩前
- 用户手动触发上下文压缩前
- 任何可能导致上下文截断的操作前

### 恢复策略

压缩完成后，Agent 从 `.agent_cache/` 目录读取持久化的状态文件，恢复 Decision Log、当前 Phase 和工作流状态，确保工作流不因上下文压缩而中断。

## 辅助脚本

脚本路径：`scripts/session-persist.py`

### save_session()

生成会话摘要文件，保存到 `.skill-logs/session-{timestamp}.md`。

功能：

- 收集当前会话的已完成任务、未完成任务、关键决策和经验沉淀
- 按照标准格式生成摘要文件
- 自动创建 `.skill-logs/` 目录（如不存在）
- 返回生成的摘要文件路径

### load_last_session()

加载最近的会话摘要文件。

功能：

- 扫描 `.skill-logs/` 目录下的所有 `session-*.md` 文件
- 按时间戳降序排序
- 读取并解析最近一个摘要文件
- 返回解析后的结构化摘要数据
- 如无历史摘要，返回空结构

### list_sessions()

列出所有会话摘要文件。

功能：

- 扫描 `.skill-logs/` 目录下的所有 `session-*.md` 文件
- 按时间戳降序排序
- 返回摘要文件列表，包含时间戳和文件路径
- 支持分页参数，控制返回数量
