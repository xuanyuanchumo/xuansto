# /execute-plan 命令

## 命令描述

基于计划文件启动子代理调度流程，将原子任务分派给独立子代理执行，并通过两阶段审查确保交付质量。该命令支持并行/串行智能调度、计划合规性审查、代码质量审查和返工管理。

## 触发条件

| 触发方式 | 说明 |
|----------|------|
| 命令输入 | 用户输入 `/execute-plan` |
| 关键词触发 | 用户提及"执行计划"、"调度子代理"、"execute plan" |
| 自动触发 | `/plan` 命令完成后自动建议 |
| 流程触发 | 设计文档确认后进入实施阶段 |

## 命令名称与语法

```
/execute-plan [plan-file] [--parallelism=<并行数>] [--max-rework=<返工上限>]
```

## 参数定义

| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| `[plan-file]` | path | 否 | .agent_cache/<task>/implementation-plan.md | 计划文件路径 |
| `--parallelism` | int | 否 | 3 | 最大并行子代理数 |
| `--max-rework` | int | 否 | 3 | 单任务最大返工次数 |
| `--skip-stage1` | flag | 否 | false | 跳过Stage 1计划合规性审查（不推荐） |
| `--skip-stage2` | flag | 否 | false | 跳过Stage 2代码质量审查（不推荐） |
| `--dry-run` | flag | 否 | false | 仅分析任务依赖，不实际执行 |

### 步骤详情

1. **Step 1: 解析原子任务列表**
   - 读取计划文件，提取任务列表
   - 验证每个任务的原子性（≤5分钟、含文件路径、含验证步骤）
   - 对非原子任务进行二次拆分
   - 生成标准化原子任务列表

2. **Step 2: 识别独立任务 vs 依赖任务**
   - 构建任务依赖图（DAG）
   - 检测循环依赖
   - 识别可并行任务组和串行任务链
   - 计算关键路径

3. **Step 3: 为每个任务创建独立子代理**
   - 根据任务类型匹配Agent能力
   - 创建独立子代理实例，注入干净上下文
   - 按并行/串行策略调度执行

4. **Step 4: 两阶段审查**
   - **Stage 1**: 计划合规性审查（规格覆盖、接口契约、数据模型、验收标准、范围控制）
   - **Stage 2**: 代码质量审查（圈复杂度≤10、无硬编码、覆盖率≥80%、代码规范、安全扫描）

5. **Step 5: 汇总审查结果**
   - 收集所有子代理审查结果
   - 生成汇总报告，标记需返工任务
   - 统计整体质量指标

6. **Step 6: 返工任务重新分派**
   - 为返工任务生成针对性修正指令
   - 重新创建子代理执行返工
   - 返工次数超过3次则上报用户

## 质量门禁

| 门禁标识 | 阶段 | 阻塞级别(BLOCK/WARN) | 通过标准 |
|----------|------|----------------------|----------|
| PLAN-ATOMIC | Phase 2 | BLOCK | 每个任务≤5分钟+含文件路径+含验证步骤 |
| SUBAGENT-REVIEW | Phase 4 | BLOCK | 两阶段审查通过+无返工任务 |

execute-plan完成后自动执行：

- [ ] 所有任务满足原子性标准
- [ ] 两阶段审查全部通过
- [ ] 无需返工的任务（或返工已全部完成）
- [ ] 审查汇总报告已生成

## 返工管理

当任务审查未通过时，系统自动进入返工流程：

```
🔄 返工任务: T002 (第1/3次)

📋 失败原因: 接口契约不匹配
   - 预期: POST /api/users 返回201
   - 实际: POST /api/users 返回200

🔧 修正要求:
   1. 修改API返回状态码为201
   2. 更新对应测试用例

⏳ 重新分派中...
```

**返工上限规则**：
- 同一任务最多返工3次
- 第3次返工仍失败 → BLOCKED，上报用户决策
- 返工模式记录到知识库
